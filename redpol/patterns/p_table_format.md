## 1. Назначение паттерна

Паттерн описывает правила форматирования данных в таблицах: типы данных в ячейках, горизонтальное и вертикальное выравнивание, оформление заголовков колонок, работу с повторяющимися значениями, а также рекомендуемые размеры ячеек.

Правильное форматирование данных облегчает чтение таблицы и ускоряет работу пользователя.

---

## 2. Типы данных в ячейке

В ячейку таблицы можно положить один из следующих типовов данных.

| Тип данных | Примеры | Базовое правило |
|---|---|---|
| Текстовые данные | Назначение, статус, название, ссылка | Выравниваются по левому краю |
| Числовые данные с размерностью | Сумма, процентная ставка | Выравниваются по правому краю |
| Числовые данные без размерности | Номер телефона, дата, номер счёта | Выравниваются по левому краю |
| Графика | Миниатюра карточки, IconView, картинка | Выравнивается по левому краю |
| Интерфейсные элементы | Чекбоксы, шевроны, кнопки действий | Выравниваются по левому или правому краю |

---

## 3. Горизонтальное выравнивание

### 3.1. Текстовые данные

Текстовые данные всегда выравниваются по левому краю.

**Примеры:**

- название;
- статус;
- назначение;
- ссылка;
- описание;
- тип документа;
- название компании.

---

### 3.2. Числовые данные с размерностью

Числовые данные с размерностью всегда выравниваются по правому краю.

**Примеры:**

- сумма;
- остаток;
- стоимость;
- процентная ставка;
- рост в сантиметрах;
- сумма в рублях.

**Пример правила:**

```md
Сумма → по правому краю
Остаток → по правому краю
Стоимость, ₽ → по правому краю
```

---

### 3.3. Комплексные параметры

Комплексный параметр вида `Ширина × Высота × Глубина` выравнивается по левому краю.

Отдельные числовые параметры с размерностью выравниваются по правому краю.

```md
120 × 80 × 40 см → по левому краю
Рост, см → по правому краю
Вес, кг → по правому краю
```

---

### 3.4. Числовые данные без размерности

Числовые данные без размерности всегда выравниваются по левому краю.

**Примеры:**

- номер телефона;
- дата;
- номер счёта;
- ИНН;
- номер документа.

```md
Дата → по левому краю
Номер → по левому краю
ИНН → по левому краю
```

---

### 3.5. Графика

Графика выравнивается по левому краю.

**Примеры:**

- миниатюра;
- аватар;
- IconView;
- картинка.

---

### 3.6. Интерфейсные элементы

Интерфейсные элементы могут выравниваться по левому или правому краю — в зависимости от роли элемента и конструкции таблицы.

**Примеры:**

- чекбокс;
- шеврон;
- кнопка действия;
- иконка действия.

---

## 4. Выравнивание заголовков колонок

Заголовки колонок наследуют выравнивание от содержимого ячеек.

```md
Если значения в колонке выровнены по левому краю,
заголовок тоже выравнивается по левому краю.

Если значения в колонке выровнены по правому краю,
заголовок тоже выравнивается по правому краю.
```

**Примеры:**

| Колонка | Тип данных | Выравнивание значения | Выравнивание заголовка |
|---|---|---:|---:|
| Покупатель | Текст | Слева | Слева |
| ИНН | Число без размерности | Слева | Слева |
| Номер | Число без размерности | Слева | Слева |
| Дата открытия | Дата | Слева | Слева |
| Статус | Текст | Слева | Слева |
| Сумма, ₽ | Число с размерностью | Справа | Справа |

---

## 5. Вертикальное выравнивание

Независимо от типа данных, почти во всех случаях ячейки выравниваются по верхнему краю.

```md
Вертикальное выравнивание: top
```

### Не допускается

```md
Вертикальное выравнивание по центру — не допускается.
Вертикальное выравнивание по нижнему краю — не допускается.
```

Особенно важно соблюдать это правило в гибкой таблице: выравнивание всегда должно быть по верхнему краю.

---

## 6. Типичные ошибки

### 6.1. Сумма выровнена не по правому краю

**Не ок**

```md
Сумма выровнена по левому краю
```

**Ок**

```md
Сумма выровнена по правому краю
```

---

### 6.2. Статус выровнен по правому краю

Статус относится к текстовому типу данных и всегда выравнивается по левому краю.

**Не ок**

```md
Статус → по правому краю
```

**Ок**

```md
Статус → по левому краю
```

---

### 6.3. Дата или номер выровнены по правому краю

Дата и номер относятся к числовым данным без размерности и всегда выравниваются по левому краю.

**Не ок**

```md
Дата → по правому краю
Номер → по правому краю
```

**Ок**

```md
Дата → по левому краю
Номер → по левому краю
```

---

### 6.4. Заголовок не наследует выравнивание ячейки

Заголовок колонки должен быть выровнен так же, как значения в этой колонке.

**Не ок**

```md
Значения суммы выровнены вправо,
а заголовок «Сумма» — влево.
```

**Ок**

```md
Значения суммы выровнены вправо,
и заголовок «Сумма» тоже выровнен вправо.
```

---

## 7. Длина заголовка

Названия колонок должны быть краткими.

Если заголовок не умещается по ширине, текст скрывается через эллипсис.

```md
Дата открытия → Дата откры…
```

При ховере на ячейку заголовка нужно показывать системную подсказку с полным текстом заголовка.

### Не допускается

В широкой и базовой таблице не переносим заголовок на вторую строку.

```md
Дата
открытия
```

### Допускается

```md
Дата откры…
```

С подсказкой при наведении:

```md
Дата открытия
```

---

## 8. Повторения в значениях ячеек

Нужно избегать повторений в значениях ячеек одного столбца, если размерность заранее известна из контекста или заголовка.

### Пример

Если весь столбец содержит суммы в рублях, символ рубля лучше вынести в заголовок.

**Не ок**

```md
210 000,06 ₽
25 000,26 ₽
16 000,00 ₽
```

**Ок**

```md
Сумма, ₽

210 000,06
25 000,26
16 000,00
```

## 9. Размеры ячеек

## 9.1. Ширина

Так как в гибкой таблице пользователь может самостоятельно менять ширину столбцов, рекомендации по ширине в первую очередь относятся к обычной таблице и значению гибкой таблицы по умолчанию.

### Рекомендация для текстовых данных

Максимальная длина строки для текстовых данных:

```md
480 px
или
60–70 знаков
```

Ширина рассчитана на основе стиля:

```md
Paragraph/14–20 Primary Small
```

Если используется другой кегль, ширину нужно пересчитать самостоятельно.

---

### 9.2. Однотипные колонки

Для однотипных колонок лучше использовать как можно меньше разных ширин.

```md
Чем меньше разных ширин колонок, тем лучше.
```

---

## 10. Высота ячеек

Длинный текст в ячейке читать труднее, особенно если количество строк сильно отличается от ячейки к ячейке.

Взгляд проваливается в белое пространство и теряет линию чтения.

### Рекомендация

Для обычной и гибкой таблицы:

```md
Не больше 3 строк в ячейке.
```

## 12. Сжатая версия для RAG

Паттерн «Форматирование данных в таблице» задаёт правила выравнивания и размеров ячеек. Текстовые данные, графика, даты, номера телефонов, номера счетов, ИНН и другие числовые данные без размерности выравниваются по левому краю. Числовые данные с размерностью, например суммы, проценты, стоимость и отдельные параметры вроде роста в сантиметрах, выравниваются по правому краю. Комплексные параметры вида «Ширина × Высота × Глубина» выравниваются по левому краю. Заголовки колонок наследуют выравнивание содержимого ячеек. По вертикали ячейки почти всегда выравниваются по верхнему краю; выравнивание по центру и по нижнему краю не допускается. Заголовки колонок должны быть краткими, не переноситься на вторую строку в базовой и широкой таблице, а при нехватке места скрываться через эллипсис с подсказкой по ховеру. Повторяющиеся размерности в значениях ячеек нужно выносить в заголовок колонки. Для текстовых данных рекомендуемая максимальная длина строки — 480 px или 60–70 знаков. В обычной и гибкой таблице рекомендуется не больше трёх строк текста в ячейке.
