## Section 1: Определение

Паттерн описывает правила форматирования данных в таблицах: типы данных в ячейках, горизонтальное и вертикальное выравнивание, оформление заголовков колонок, работу с повторяющимися размерностями и рекомендуемые размеры ячеек.

Правильное форматирование облегчает чтение таблицы и ускоряет работу пользователя.

## Section 2: Когда использовать

Используйте паттерн, когда проектируете или проверяете таблицы с:

- текстовыми данными: назначение, статус, название, ссылка, описание, тип документа, название компании;
- числовыми данными с размерностью: сумма, остаток, стоимость, процентная ставка, рост, вес;
- числовыми данными без размерности: номер телефона, дата, номер счёта, ИНН, номер документа;
- графикой: миниатюра, аватар, `IconView`, картинка;
- интерфейсными элементами: чекбокс, шеврон, кнопка действия, иконка действия.

## Section 3: Когда не использовать

Не используйте паттерн как замену компонентным правилам самой таблицы, если нужно определить поведение сортировки, пагинации, выбора строк, массовых действий или адаптива таблицы.

Не используйте правила выравнивания чисел с размерностью для дат, номеров, телефонов, ИНН и номеров счетов: они выглядят как числа, но читаются как идентификаторы.

## Section 4: Принципы

1. Тип данных определяет выравнивание.
2. Заголовок колонки наследует выравнивание значений.
3. Ячейки почти всегда выравниваются по верхнему краю.
4. Повторяющуюся размерность лучше вынести в заголовок колонки.
5. Заголовки должны быть короткими и не переноситься в базовой и широкой таблице.
6. Длинный текст в ячейках нужно ограничивать, чтобы таблица не теряла линию чтения.

## Section 5: Структура текста

Заголовок колонки должен кратко называть данные. Если заголовок не помещается по ширине, скрывайте текст через эллипсис и показывайте полную формулировку в системной подсказке по ховеру.

Повторяющиеся единицы измерения и валюты переносите в заголовок, если вся колонка содержит значения в одной размерности.

Для текстовых данных ориентируйтесь на максимальную длину строки `480 px` или `60-70` знаков. В обычной и гибкой таблице рекомендуется не больше трёх строк текста в ячейке.

## Section 6: Правила

### Rule 1: Выравнивай текстовые данные по левому краю

- ruleId: rule:tables.data-formatting.text-left
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: partial

Текстовые данные в таблице всегда выравниваются по левому краю.

#### Правильно

```text
Статус -> по левому краю
```

#### Неправильно

```text
Статус -> по правому краю
```

#### Почему

Текст удобнее читать от общего левого края, особенно когда в колонке значения разной длины.

### Rule 2: Выравнивай числовые данные с размерностью по правому краю

- ruleId: rule:tables.data-formatting.dimension-right
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: partial

Суммы, проценты, стоимость и отдельные числовые параметры с размерностью выравниваются по правому краю.

#### Правильно

```text
Сумма, ₽ -> по правому краю
```

#### Неправильно

```text
Сумма, ₽ -> по левому краю
```

#### Почему

Правое выравнивание помогает сравнивать разряды и быстрее считывать числовые значения.

### Rule 3: Выравнивай числовые данные без размерности по левому краю

- ruleId: rule:tables.data-formatting.number-without-dimension-left
- severity: error
- appliesTo: component
- checkType: dictionary
- autofix: partial

Даты, номера телефонов, номера счетов, ИНН и номера документов выравниваются по левому краю.

#### Правильно

```text
ИНН -> по левому краю
Дата -> по левому краю
```

#### Неправильно

```text
ИНН -> по правому краю
Дата -> по правому краю
```

#### Почему

Такие значения читаются как идентификаторы или даты, а не как величины для сравнения разрядов.

### Rule 4: Выравнивай комплексные параметры по левому краю

- ruleId: rule:tables.data-formatting.complex-parameter-left
- severity: warning
- appliesTo: component
- checkType: dictionary
- autofix: partial

Комплексный параметр вида `Ширина x Высота x Глубина` выравнивается по левому краю. Отдельные параметры с размерностью можно выравнивать по правому краю.

#### Правильно

```text
120 x 80 x 40 см -> по левому краю
```

#### Неправильно

```text
120 x 80 x 40 см -> по правому краю
```

#### Почему

Комплексный параметр читается как составная строка, а не как одно число.

### Rule 5: Выравнивай графику по левому краю

- ruleId: rule:tables.data-formatting.graphics-left
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: partial

Миниатюры, аватары, `IconView` и картинки выравниваются по левому краю.

#### Правильно

```text
IconView -> по левому краю
```

#### Неправильно

```text
IconView -> по правому краю без причины
```

#### Почему

Графика в ячейке должна начинаться от той же визуальной оси, что и другой контент таблицы.

### Rule 6: Наследуй выравнивание заголовка от ячеек

- ruleId: rule:tables.data-formatting.header-inherits-cell-alignment
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: partial

Заголовок колонки выравнивается так же, как значения в этой колонке.

#### Правильно

```text
Значения суммы выровнены вправо, заголовок «Сумма» тоже вправо.
```

#### Неправильно

```text
Значения суммы выровнены вправо, заголовок «Сумма» влево.
```

#### Почему

Единое выравнивание связывает заголовок с содержимым и упрощает сканирование таблицы.

### Rule 7: Выравнивай ячейки по верхнему краю

- ruleId: rule:tables.data-formatting.vertical-top
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: partial

Почти во всех случаях ячейки выравниваются по верхнему краю. Не выравнивайте содержимое по центру или нижнему краю.

#### Правильно

```text
vertical align: top
```

#### Неправильно

```text
vertical align: center
```

#### Почему

В гибкой таблице верхнее выравнивание сохраняет линию чтения при разной высоте строк.

### Rule 8: Не переноси заголовок в базовой и широкой таблице

- ruleId: rule:tables.data-formatting.header-no-wrap
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: partial

В широкой и базовой таблице заголовок не переносится на вторую строку. Если места не хватает, используйте эллипсис и подсказку по ховеру.

#### Правильно

```text
Дата откры...
```

#### Неправильно

```text
Дата
открытия
```

#### Почему

Переносы в заголовках увеличивают высоту шапки и ухудшают сравнение колонок.

### Rule 9: Выноси повторяющуюся размерность в заголовок

- ruleId: rule:tables.data-formatting.no-repeated-units
- severity: warning
- appliesTo: text
- checkType: llm
- autofix: partial

Если вся колонка содержит значения в одной валюте или размерности, вынесите размерность в заголовок и не повторяйте её в каждой ячейке.

#### Правильно

```text
Сумма, ₽
210 000,06
25 000,26
```

#### Неправильно

```text
210 000,06 ₽
25 000,26 ₽
```

#### Почему

Повторяющиеся символы создают шум и замедляют чтение таблицы.

### Rule 10: Ограничивай длину текста в ячейке

- ruleId: rule:tables.data-formatting.cell-text-length
- severity: recommendation
- appliesTo: component
- checkType: deterministic
- autofix: no

Для текстовых данных используйте максимум `480 px` или `60-70` знаков в строке. В ячейке рекомендуется не больше трёх строк.

#### Правильно

```text
Текст в ячейке занимает до 3 строк.
```

#### Неправильно

```text
Текст в ячейке занимает 6 строк и ломает высоту таблицы.
```

#### Почему

Слишком длинный текст создаёт много пустого пространства и сбивает пользователя с линии чтения.

## Section 7: Шаблоны

### Текстовая колонка

```text
Название колонки -> align left
Значения -> align left
```

### Колонка с суммой

```text
Сумма, ₽ -> align right
Значения -> align right
```

### Колонка с идентификатором

```text
ИНН -> align left
Номер счёта -> align left
Дата -> align left
```

### Длинный заголовок

```text
Дата откры...
Tooltip: Дата открытия
```

### Повторяющаяся размерность

```text
Сумма, ₽
210 000,06
25 000,26
16 000,00
```

## Section 8: Примеры

### Пример 1: Сумма

```text
Сумма, ₽ -> по правому краю
```

Сумма является числовым значением с размерностью, поэтому выравнивается вправо.

### Пример 2: Дата

```text
Дата открытия -> по левому краю
```

Дата выглядит как числовое значение, но читается как идентификатор времени, поэтому выравнивается влево.

### Пример 3: Комплексный параметр

```text
120 x 80 x 40 см -> по левому краю
```

Составное значение читается как строка.

### Пример 4: Заголовок суммы

```text
Значения суммы выровнены вправо.
Заголовок «Сумма, ₽» выровнен вправо.
```

Заголовок наследует выравнивание значений.

## Section 9: Антипримеры

### Антипример 1: Статус выровнен вправо

```text
Статус -> по правому краю
```

Статус относится к текстовым данным и должен быть выровнен влево.

### Антипример 2: Дата выровнена вправо

```text
Дата -> по правому краю
```

Дата относится к числовым данным без размерности и должна быть выровнена влево.

### Антипример 3: Заголовок не наследует выравнивание

```text
Значения суммы выровнены вправо, а заголовок «Сумма» влево.
```

Заголовок должен повторять выравнивание колонки.

### Антипример 4: Перенос заголовка

```text
Дата
открытия
```

В базовой и широкой таблице используйте эллипсис и подсказку, а не перенос.

### Антипример 5: Повтор валюты в каждой ячейке

```text
210 000,06 ₽
25 000,26 ₽
16 000,00 ₽
```

Если вся колонка в рублях, валюту лучше вынести в заголовок.

## Section 10: Машинная обработка

### Детерминированные проверки

- Проверять выравнивание текстовых колонок по левому краю.
- Проверять выравнивание сумм, процентов и других чисел с размерностью по правому краю.
- Проверять выравнивание заголовка по выравниванию значений колонки.
- Проверять вертикальное выравнивание ячеек по верхнему краю.
- Проверять, что заголовок в базовой и широкой таблице не переносится на вторую строку.
- Проверять эллипсис и наличие подсказки для обрезанного заголовка.
- Проверять ограничение текста в ячейке до трёх строк.

### Словарные проверки

- Определять даты, телефоны, ИНН, номера счетов и номера документов как числовые данные без размерности.
- Определять суммы, проценты, стоимость, рост, вес и другие размерные величины.
- Находить повторяющиеся символы валюты и единицы измерения в ячейках одной колонки.

### LLM-проверки

- Проверять, что выбранный тип данных соответствует содержимому колонки.
- Проверять, что повторяющаяся размерность действительно может быть вынесена в заголовок.
- Проверять, что комплексные параметры не ошибочно трактуются как одно число с размерностью.
- Проверять, что ширина текстовой колонки не ухудшает чтение таблицы.

### Не проверяется автоматически

- Удобство чтения таблицы в реальном сценарии.
- Корректность ширины колонки при нестандартном кегле.
- Полная логика гибкой таблицы и пользовательского ресайза колонок.
- Обоснованность интерфейсных элементов в конкретной колонке.

### Автоисправления

- Выставить левое выравнивание для текстовых данных.
- Выставить правое выравнивание для числовых данных с размерностью.
- Выставить левое выравнивание для дат, номеров, телефонов, ИНН и номеров счетов.
- Синхронизировать выравнивание заголовка с выравниванием значений.
- Заменить перенос длинного заголовка на эллипсис, если доступна полная подсказка.
