## Section 1: Определение

Адаптив в Альфа-Бизнес — это правила проектирования и отрисовки интерфейсов для разных размеров экранов в desktop и Mobile Web.

Паттерн описывает, под какие разрешения рисовать макеты, какие брейкпоинты использовать, как сохранять функциональность при изменении ширины окна и как выбирать версию интерфейса для Mobile Web.

## Section 2: Когда использовать

Используй паттерн, когда проектируешь:

- desktop-экран Альфа-Бизнеса;
- адаптивную версию desktop-сценария для Mobile Web;
- отдельную мобильную версию web-сценария;
- поведение страницы при изменении ширины браузера;
- верхнее меню, фон страницы, сетку и базовую компоновку для разных разрешений.

Паттерн нужен, если интерфейс должен корректно работать на ширинах от `320 px` до широких desktop-экранов.

## Section 3: Когда не использовать

Не используй паттерн как замену компонентным гайдам. Если поведение конкретного компонента описано в его паттерне или описании, сначала проверяй компонентный источник.

Не используй адаптив как способ убрать важную функциональность внутри одного канала. При изменении ширины окна пользователь должен сохранять доступ к действиям, которые доступны в этом канале.

Не проектируй Mobile Web как механическое уменьшение desktop-экрана, если сценарий требует отдельной мобильной логики.

## Section 4: Принципы

- Проектируй desktop first: сначала проработай основной desktop-сценарий, затем адаптируй его для меньших ширин.
- Проверяй интерфейс на базовых разрешениях: `1600 × 900`, `768 × 1024`, `375 × 812`.
- При сложной композиции дополнительно проверяй `1440 px` и `1280 px`.
- Изменение ширины окна браузера не считается сменой канала.
- Функциональность внутри одного канала должна сохраняться при любом изменении ширины в пределах этого канала.
- При смене канала состав функциональности может отличаться, если это решение принял владелец продукта.
- В Mobile Web сценарий должен быть представлен хотя бы в виде заглушки.

## Section 5: Структура текста

### Обязательные элементы

- Описание целевых разрешений для проверки макета.
- Брейкпоинты и правила поведения для `MobileWeb` и `Desktop`.
- Правила сохранности функциональности внутри канала.
- Правила выбора отдельной мобильной или адаптивной версии.
- Правила для базовых элементов страницы: фон, верхнее меню, левое меню, сетка и подвал.

### Необязательные элементы

- Дополнительные разрешения для проверки сложных сценариев.
- Заглушка для Mobile Web, если продукт недоступен в мобильном канале.
- Ссылки на связанные паттерны, компоненты и описания.

### Базовые разрешения

- Обычный desktop: `1600 × 900 px`.
- Маленький desktop: `768 × 1024 px`.
- Mobile Web: `375 × 812 px`.

Эти размеры проверяют поведение контента при изменении ширины контентной зоны: `1248 → 704 → 335`.

## Section 6: Правила

### Rule 1: Рисуй три базовых размера макета

- ruleId: rule:layout.adaptive-alfa-business.base-artboards
- severity: error
- appliesTo: screen
- checkType: manual
- autofix: no

Для адаптива в Альфа-Бизнес проверяй макет на трёх базовых размерах: обычный desktop `1600 × 900 px`, маленький desktop `768 × 1024 px` и Mobile Web `375 × 812 px`.

#### Правильно

```text
Desktop: 1600 × 900 px
Small desktop: 768 × 1024 px
Mobile Web: 375 × 812 px
```

#### Неправильно

```text
Проверен только экран 1440 px
```

#### Почему

Три размера показывают, как меняется контентная зона, сетка и компоновка на ключевых состояниях интерфейса.

### Rule 2: Проверяй дополнительные ширины для сложных композиций

- ruleId: rule:layout.adaptive-alfa-business.extra-widths-for-complex-layouts
- severity: warning
- appliesTo: screen
- checkType: manual
- autofix: no

Если композиция сложная или ожидается нестандартное перестроение страницы, дополнительно проверяй экран на ширинах `1440 px` и `1280 px`.

#### Правильно

```text
Для страницы со сложной правой колонкой проверены 1600, 1440, 1280, 768 и 375 px
```

#### Неправильно

```text
Сложная страница проверена только на 1600 и 375 px
```

#### Почему

Промежуточные ширины помогают поймать проблемы сетки, переполнения и переноса элементов до передачи в разработку.

### Rule 3: Сохраняй функциональность внутри канала

- ruleId: rule:layout.adaptive-alfa-business.keep-functionality-within-channel
- severity: error
- appliesTo: flow
- checkType: llm
- autofix: no

Функциональность, доступная пользователю в рамках одного канала, должна сохраняться при изменении ширины окна в пределах диапазона этого канала.

#### Правильно

```text
Кнопка переехала в меню «Ещё», но действие осталось доступным
```

#### Неправильно

```text
При сужении окна действие полностью исчезло без альтернативного доступа
```

#### Почему

Изменение ширины браузера не является сменой канала и не должно ограничивать действия пользователя.

### Rule 4: Не меняй бизнес-логику при изменении ширины окна

- ruleId: rule:layout.adaptive-alfa-business.no-business-logic-change-on-resize
- severity: error
- appliesTo: flow
- checkType: manual
- autofix: no

При изменении ширины браузера можно менять компоновку, визуальное представление, расположение элементов и сворачивать второстепенные блоки, но нельзя менять бизнес-логику или сценарий.

#### Правильно

```text
Фильтры свернулись, но набор доступных условий и результат поиска не изменились
```

#### Неправильно

```text
На меньшей ширине пользователь больше не может подписать документ
```

#### Почему

Пользователь работает в том же канале, поэтому сценарий должен оставаться тем же.

### Rule 5: Различай Mobile Web и адаптивную версию

- ruleId: rule:layout.adaptive-alfa-business.mobileweb-version-choice
- severity: warning
- appliesTo: flow
- checkType: manual
- autofix: no

Для Mobile Web выбери тип реализации: отдельная мобильная версия, адаптивная версия desktop-сценария или заглушка. Решение принимает владелец продукта.

#### Правильно

```text
Desktop → Mobile Web: адаптивная версия на основе desktop-функциональности
Desktop → Mobile Web: отдельная мобильная версия на основе АБМ-паттернов
Desktop → Mobile Web: заглушка, если сценарий недоступен в мобильном канале
```

#### Неправильно

```text
Mobile Web не спроектирован, потому что сценарий есть только в desktop
```

#### Почему

Любой сценарий должен быть представлен в Mobile Web хотя бы заглушкой.

### Rule 6: Используй правильные брейкпоинты

- ruleId: rule:layout.adaptive-alfa-business.breakpoints
- severity: error
- appliesTo: screen
- checkType: deterministic
- autofix: no

Используй канальные брейкпоинты: `MobileWeb` — `320–767 px`, `Desktop` — от `768 px` и до бесконечности.

#### Правильно

```text
320–767 px → MobileWeb
768 px и больше → Desktop
```

#### Неправильно

```text
MobileWeb начинается с 768 px
Desktop начинается с 1024 px
```

#### Почему

Брейкпоинты определяют версию компонентов, меню, сетку и доступный набор сценарных решений.

### Rule 7: Настраивай Mobile Web как мобильный канал

- ruleId: rule:layout.adaptive-alfa-business.mobileweb-settings
- severity: error
- appliesTo: screen
- checkType: manual
- autofix: no

Для ширин `320–767 px` используй Mobile Web: специальные `[MW]` или адаптивные `[M]` версии desktop-компонентов, контентную область максимум `600 px`, `[M] NavigationBar`, страницу `Page :: OnWhite` и без левого меню.

#### Правильно

```text
MobileWeb 375 px
Page :: OnWhite
[M] NavigationBar
Контентная область: 335 px
```

#### Неправильно

```text
MobileWeb 375 px
[D] Header
[D] SideMenu
Page :: OnGrey
```

#### Почему

Mobile Web должен восприниматься как мобильный канал, а не как сжатая desktop-страница.

### Rule 8: Настраивай desktop 768–1023 как маленький desktop

- ruleId: rule:layout.adaptive-alfa-business.small-desktop-settings
- severity: error
- appliesTo: screen
- checkType: manual
- autofix: no

Для ширин `768–1023 px` используй desktop-компоненты `[D]`, контентную область максимум `959 px`, `[D](768) HeaderMenu`, `Page :: OnGrey`, сетку `12` колонок и без левого меню.

#### Правильно

```text
Desktop 768 px
[D](768) HeaderMenu
Page :: OnGrey
12 колонок, весь контент занимает 12 колонок
```

#### Неправильно

```text
Desktop 768 px
[D] SideMenu
Основной контент 8 колонок + правая колонка 4 колонки
```

#### Почему

На маленьком desktop меню прячется в бургер, а контентная зона близка к экрану `1024 px`.

### Rule 9: Настраивай desktop 1024+ как полноценную desktop-версию

- ruleId: rule:layout.adaptive-alfa-business.full-desktop-settings
- severity: error
- appliesTo: screen
- checkType: manual
- autofix: no

Для ширин от `1024 px` используй desktop-компоненты `[D]`, `[D] Header`, `[D] SideMenu`, `Page :: OnGrey`, сетку `12` колонок и контентную область максимум `1248 px`.

#### Правильно

```text
Desktop 1600 px
[D] Header
[D] SideMenu
Page :: OnGrey
Контентная область: до 1248 px
```

#### Неправильно

```text
Desktop 1600 px
[M] NavigationBar
Page :: OnWhite
```

#### Почему

Ширины от `1024 px` показывают полноценную desktop-версию с левым меню и desktop-навигацией.

### Rule 10: Сохраняй минимальную ширину desktop 768 px

- ruleId: rule:layout.adaptive-alfa-business.desktop-min-width
- severity: error
- appliesTo: screen
- checkType: deterministic
- autofix: no

Для desktop установлена минимальная ширина контента `768 px`. Если ширина браузера меньше `768 px`, desktop-интерфейс больше не перестраивается и появляется системный горизонтальный скролл.

#### Правильно

```text
Desktop сохраняет минимальную ширину 768 px
При меньшей ширине появляется системный горизонтальный скролл
```

#### Неправильно

```text
Desktop продолжает сжиматься ниже 768 px и ломает сетку
```

#### Почему

Ограничение защищает desktop-интерфейс от неконтролируемого сжатия.

### Rule 11: Переключай стили страницы между Desktop и Mobile Web

- ruleId: rule:layout.adaptive-alfa-business.page-style-switch
- severity: warning
- appliesTo: component
- checkType: manual
- autofix: no

В Desktop используй серый фон страницы `bg-base-alt/primary`, а в большинстве экранов Mobile Web — белый фон `bg-base/primary`. При переходе в Mobile Web переключай `BackgroundPlate` с версии `[D]` на `[M]` и выбирай соответствующий цвет фона.

#### Правильно

```text
Desktop: Page :: OnGrey, BackgroundPlate [D]
Mobile Web: Page :: OnWhite, BackgroundPlate [M]
```

#### Неправильно

```text
Mobile Web использует desktop BackgroundPlate [D] и серый фон без причины
```

#### Почему

Версии `BackgroundPlate` отличаются не только цветом, но и скруглениями.

### Rule 12: Используй мобильную навигацию в Mobile Web

- ruleId: rule:layout.adaptive-alfa-business.mobile-navigation
- severity: error
- appliesTo: component
- checkType: manual
- autofix: no

В Mobile Web используй мобильную навигацию для отдельной мобильной и адаптивной версий. Шаги, заголовок, сабтайтл и иконки команда настраивает через `CorporateAppHeaderMobile`.

#### Правильно

```text
Mobile Web: CorporateAppHeaderMobile
```

#### Неправильно

```text
Mobile Web: desktop Header и SideMenu
```

#### Почему

Mobile Web должен использовать мобильную навигационную модель.

### Rule 13: Не используй подвал

- ruleId: rule:layout.adaptive-alfa-business.no-footer
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Подвал в Альфа-Бизнес не используется с мая 2024 года.

#### Правильно

```text
Страница без footer
```

#### Неправильно

```text
© 2001—2024 Альфа-Банк. Генеральная лицензия ЦБ РФ №1326.
```

#### Почему

Footer исключён из актуального паттерна страницы.

## Section 10: Машинная обработка

### Детерминированные проверки

- Наличие базовых макетов `1600 × 900`, `768 × 1024`, `375 × 812`.
- Использование брейкпоинтов `320–767` для Mobile Web и `768+` для Desktop.
- Минимальная ширина desktop `768 px`.
- Отсутствие footer-компонента.
- Наличие `figmaLink` в метаданных.

### Словарные проверки

- Предпочтительные термины: `Mobile Web`, `Desktop`, `Page :: OnWhite`, `Page :: OnGrey`, `BackgroundPlate`, `NavigationBar`, `HeaderMenu`, `SideMenu`.
- Нежелательные формулировки: `мобильный desktop`, `сжатый desktop`, `скрыть функциональность без альтернативы`.

### LLM-проверки

- Сохраняется ли функциональность внутри канала при изменении ширины.
- Не меняется ли бизнес-логика при адаптации.
- Корректно ли выбран тип Mobile Web-реализации: отдельная версия, адаптивная версия или заглушка.
- Не используется ли desktop-логика в мобильном канале без причины.
- Показана ли критичная функциональность через альтернативный UI-механизм, если она скрыта из видимой области.

### Не проверяется автоматически

- Решение владельца продукта о составе функциональности между каналами.
- Нужны ли дополнительные проверки на `1440 px` и `1280 px` для конкретной сложной композиции.
- Корректность всех компонентных настроек без доступа к Figma-структуре.
- Канонический Figma-источник паттерна, если ссылка не указана в PDF.

### Автоисправления

- `partial`: предложить корректный брейкпоинт, страницу, меню или текст заглушки.
- `no`: менять бизнес-логику, состав функциональности между каналами или тип Mobile Web-реализации автоматически нельзя.
