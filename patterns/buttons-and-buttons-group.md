## Section 1: Определение

Кнопка — это элемент интерфейса для запуска действия, подтверждения выбора или перехода к следующему шагу.

Группа кнопок помогает показать несколько связанных действий и сделать их приоритет понятным с первого взгляда.

В рамках этого паттерна рядом с кнопками рассматриваем и `Link`, если он участвует в иерархии действий на экране.

## Section 2: Когда использовать

Используй паттерн, когда пользователю нужно:

- выполнить явное действие;
- подтвердить выбор;
- сохранить результат;
- перейти к следующему шагу;
- открыть дополнительный сценарий;
- выбрать одно из нескольких связанных действий.

Типовые компоненты:

- `Button` как основное действие;
- `CustomButton`, если нужен кастомный вид и платформа это допускает;
- `PickerButton`, если часть действий нужно скрыть;
- `IconButton`, если смысл иконки однозначен из контекста;
- `ActionButton` на мобильных устройствах для действий одинакового приоритета;
- `Link`, если нужен именно переход, а не команда.

## Section 3: Когда не использовать

Не используй паттерн, если:

- элемент должен показывать состояние, а не запускать действие;
- на экране много второстепенных действий и их можно безопасно спрятать в меню;
- текст нужен как пояснение, а не как команда;
- смысл иконки неочевиден без подписи и контекста;
- в desktop приходится использовать запрещённые для платформы варианты ради декоративности.

Не делай кнопку контейнером для объяснений, статусов или служебных подсказок.

## Section 4: Принципы

- Показывай пользователю действие, а не абстрактное состояние.
- Сохраняй одну понятную иерархию действий внутри группы.
- Оставляй на экране только действительно важные действия.
- Проверяй платформенные ограничения до публикации.
- Не меняй встроенный текст компонента без необходимости.
- Для загрузки используй спиннер и не меняй ширину кнопки.
- В desktop не добавляй `Hint` внутрь кнопки.

## Section 5: Структура текста

### Обязательные элементы

- У каждой кнопки должен быть понятный `Label`, если это не чистый `IconButton`.
- В группе кнопок должно быть понятно, какое действие главное, а какие второстепенные.

### Необязательные элементы

- `Hint` внутри кнопки допустим только в размере `56` в `mobileweb`.
- `Loading state` со спиннером используем, когда действие уже запущено.
- `PickerButton` используем, если действия не помещаются или перегружают интерфейс.
- `Link` используем для перехода, если не нужен акцент основной кнопки.

### Платформенные ограничения

В `desktop` не используй:

- `CustomButton`;
- `View: Accent`;
- `View: Outlined`;
- `Size: 64`;
- `Size: 72`;
- `Shape: Rounded`;
- `Hint` внутри кнопки.

В АБ для `PickerButton` используй горизонтальный `kebab`.

## Section 6: Правила

### Rule 1: Пиши текст кнопки глаголом действия

- ruleId: rule:controls.buttons-and-button-groups.action-verb
- severity: error
- appliesTo: text
- checkType: llm
- autofix: partial

Текст кнопки должен называть действие, которое произойдёт после нажатия.

#### Правильно

```text
Отправить заявку
Сохранить черновик
Выбрать
```

#### Неправильно

```text
Заявка
Сохранение
Выбор
```

#### Почему

Пользователь должен сразу понимать, какое действие запустит кнопка.

### Rule 2: Не используй абстрактные и канцелярские формулировки

- ruleId: rule:controls.buttons-and-button-groups.no-abstract-labels
- severity: warning
- appliesTo: text
- checkType: dictionary
- autofix: partial

Не используй в кнопках слова, которые звучат канцелярски, слишком общо или не совпадают с живой речью интерфейса.

#### Правильно

```text
Посмотреть
На главную
Уменьшить сумму
Дальше
Хорошо
Сохранить черновик
```

#### Неправильно

```text
Просмотреть
На главный
Снизить сумму
Далее
Готово
Сохранить как черновик
```

#### Почему

Кнопка должна звучать коротко, естественно и без лишней канцелярщины.

### Rule 3: Не используй в desktop запрещённые варианты компонентов

- ruleId: rule:controls.buttons-and-button-groups.desktop-safe-variants
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В desktop не используй варианты кнопок и параметров, которые запрещены паттерном.

#### Правильно

```text
Desktop · Button · View Primary · Size 48
Desktop · Button · View Secondary · Shape Default
```

#### Неправильно

```text
Desktop · CustomButton · Size 48
Desktop · Button · View Accent · Size 64 · Shape Rounded
Desktop · Button · Hint inside
```

#### Почему

Эти варианты не соответствуют платформенному паттерну и ломают единообразие интерфейса.

### Rule 4: Ставь главное действие левее второстепенных

- ruleId: rule:controls.buttons-and-button-groups.primary-left
- severity: error
- appliesTo: component
- checkType: manual
- autofix: no

В группе кнопок главное действие всегда ставь слева. Правее располагай второстепенные действия в порядке убывания приоритета.

#### Правильно

```text
Сохранить | Отменить | Ещё
```

#### Неправильно

```text
Отменить | Сохранить | Ещё
```

#### Почему

Пользователь должен быстро считывать приоритет действий без дополнительного анализа.

### Rule 5: Уводи лишние действия в PickerButton

- ruleId: rule:controls.buttons-and-button-groups.use-picker-for-overflow
- severity: warning
- appliesTo: component
- checkType: manual
- autofix: no

Если в группе больше четырёх кнопок на desktop или первые действия получаются слишком длинными, оставляй видимыми только основные действия, а остальные уводи в `PickerButton`.

#### Правильно

```text
Подписать | Сохранить | Отменить | ⋯
```

#### Неправильно

```text
Подписать | Сохранить | Отменить | Распечатать | Скачать | Переслать
```

#### Почему

Перегруженная группа кнопок замедляет выбор и разрушает иерархию.

### Rule 6: Используй IconButton только при очевидном контексте

- ruleId: rule:controls.buttons-and-button-groups.icon-button-clear-context
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Используй `IconButton` только там, где смысл действия считывается из контекста без дополнительного пояснения.

#### Правильно

```text
В строке таблицы рядом с документом: иконка удаления
```

#### Неправильно

```text
Одинокая иконка на пустом экране без подписи и контекста
```

#### Почему

Если значение иконки неочевидно, пользователь не понимает, что произойдёт после нажатия.

## Section 7: Шаблоны

### Основное действие

```text
[Глагол] [объект]
```

Примеры:

```text
Отправить заявку
Сохранить черновик
Открыть отчёт
```

### Второстепенное действие

```text
[Глагол]
```

Примеры:

```text
Отменить
Назад
Скачать
```

### Переход по ссылке

```text
На [раздел]
```

Примеры:

```text
На главную
На витрину
```

## Section 8: Примеры

### Пример 1

Контекст: футер формы создания заявки.

```text
Отправить заявку | Сохранить черновик | Отменить
```

### Пример 2

Контекст: длинный список действий в карточке документа.

```text
Подписать | Скачать | ⋯
```

### Пример 3

Контекст: мобильный экран с несколькими действиями одинакового приоритета.

```text
Поделиться
Скачать
Повторить
```

### Пример 4

Контекст: переход в связанный раздел без акцента основной кнопки.

```text
На главную
```

## Section 9: Антипримеры

### Антипример 1

Контекст: кнопка подтверждения в модальном окне.

```text
Готово
```

Почему не работает: неясно, что именно произойдёт после нажатия.

### Антипример 2

Контекст: группа действий в карточке.

```text
Отменить | Сохранить
```

Почему не работает: второстепенное действие стоит левее главного и ломает иерархию.

### Антипример 3

Контекст: desktop-кнопка с неподдерживаемой конфигурацией.

```text
CustomButton · Accent · Rounded · 64
```

Почему не работает: конфигурация не соответствует платформенным ограничениям.

### Антипример 4

Контекст: экран без подписей и явного контекста.

```text
🗑
```

Почему не работает: действие иконки нельзя надёжно интерпретировать без дополнительных ориентиров.

## Section 10: Машинная обработка

### Детерминированные проверки

- Запрещённые desktop-варианты компонентов и параметров.
- Наличие `Hint` внутри кнопки в desktop.
- Количество видимых кнопок в группе, если компонентная разметка доступна.

### Словарные проверки

- Нежелательные формулировки: `Просмотреть`, `Далее`, `Готово`, `Сохранить как черновик`.
- Предпочтительные замены: `Посмотреть`, `Дальше`, `Хорошо`, `Сохранить черновик`.

### LLM-проверки

- Называет ли текст кнопки действие.
- Не слишком ли абстрактна или канцелярска формулировка.
- Достаточно ли понятен `IconButton` в конкретном контексте.

### Не проверяется автоматически

- Корректная бизнес-иерархия действий в конкретном сценарии.
- Решение, какие действия можно безопасно скрыть в `PickerButton`.
- Источник компонента: [Web::Core Buttons](https://www.figma.com/design/lGWq8DtnUcSkRasagBuwq6/Web-%3A%3A-Core?m=auto&node-id=2-376&t=WVFgLoKnZCNzcNwG-1)

### Автоисправления

- `partial`: предложить заменить нежелательную формулировку на словарную.
- `no`: перестраивать иерархию кнопок или менять тип компонента без подтверждения нельзя.
