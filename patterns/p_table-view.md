## Section 1: Определение

`TableView` — компонент для табличного представления данных в контентной области страницы, модального окна, сайд-панели, островка или Mobile Web-экрана.

Компонент помогает показать набор параметров и значений, когда данные нужно читать строками, сравнивать по колонкам или компактно вывести в одну вертикальную колонку.

## Section 2: Когда использовать

Используйте `TableView`, когда нужно:

- показать одну колонку данных в контентной области шириной 8 колонок;
- показать несколько колонок данных для поиска и сравнения значений;
- вывести данные в модальном окне или сайд-панели;
- показать компактный набор данных в островке;
- адаптировать табличное представление для Mobile Web;
- скрыть часть строк под раскрывающим действием `Ещё N`;
- добавить пояснение к первой колонке через `Info`-иконку;
- вынести групповые действия в `TitleView`.

## Section 3: Когда не использовать

Не используйте `TableView`, если:

- нужна полноценная интерактивная таблица с сортировкой, фильтрами, массовым выбором и табличной навигацией;
- данные лучше читаются как карточки, список или форма;
- в узкой области нужно показать много колонок без сокращения;
- важные действия со строками невозможно вынести из ячеек;
- пользователь должен редактировать значения прямо в таблице.

Для правил выравнивания, повторяющихся размерностей и длины ячеек используйте связанный паттерн `Форматирование данных в таблице`.

## Section 4: Принципы

1. Вид `TableView` выбирается по линии чтения: строками слева направо, колонками сверху вниз или вертикальным списком.
2. Компактная горизонтальная таблица подходит для одной колонки данных.
3. Многоколоночная горизонтальная таблица подходит для сравнения нескольких колонок.
4. Вертикальная таблица подходит для островков и Mobile Web.
5. Количество строк должно быть управляемым: лишние строки прячутся под `Ещё N`.
6. Текст действия раскрытия зависит от контекста данных.
7. Колонки должны описывать один тип данных, если они используются для сравнения.

## Section 5: Структура текста

В первой колонке `Caption` описывает тип данных в строке. Если текст первой колонки требует расшифровки, включайте `Info`-иконку и согласовывайте текст пояснения с редакцией.

В колонках данных `Title` и `Subtitle` описывают содержимое выбранного типа данных. Если нужны дополнительные строки или колонки, включайте их в слоях компонента.

В многоколоночной таблице тип данных в колонках `Title` должен совпадать. Если нужно пояснить часть колонок, добавьте дополнительную строку с общим заголовком.

## Section 6: Правила

### Rule 1: Используй Horizontal compact для одной колонки данных

- ruleId: rule:components.table-view.horizontal-compact-one-column
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

`Horizontal :: compact` показывает одну колонку данных. Линия чтения идёт слева направо: пользователь читает каждую строку отдельно.

#### Правильно

```text
Одна колонка данных в контентной области 8 колонок
```

#### Неправильно

```text
Несколько колонок данных собраны в Horizontal compact
```

#### Почему

Компактный горизонтальный вид рассчитан на построчное чтение, а не на сравнение нескольких колонок.

### Rule 2: Ограничивай Horizontal compact шириной контекста

- ruleId: rule:components.table-view.horizontal-compact-width
- severity: warning
- appliesTo: screen
- checkType: deterministic
- autofix: no

Используйте `Horizontal :: compact` для контентной области шириной 8 колонок, модального окна или сайд-панели не шире `800 px`.

#### Правильно

```text
Side panel 760 px -> Horizontal compact
```

#### Неправильно

```text
Широкая область 12 колонок -> Horizontal compact без причины
```

#### Почему

На широкой области компактная таблица оставляет слишком много пустого пространства и хуже использует экран.

### Rule 3: Используй Horizontal multi-column для нескольких колонок данных

- ruleId: rule:components.table-view.horizontal-multi-column
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

`Horizontal :: multi-column` показывает несколько колонок данных. Линия чтения идёт сверху вниз: пользователь ищет и сравнивает значения в таблице.

#### Правильно

```text
Несколько сотрудников сравниваются по статусу и дате.
```

#### Неправильно

```text
Одна колонка данных оформлена как multi-column.
```

#### Почему

Многоколоночный вид нужен для сравнения, а не для простого списка параметров.

### Rule 4: В узких контекстах ограничивай multi-column двумя колонками

- ruleId: rule:components.table-view.multi-column-width
- severity: warning
- appliesTo: screen
- checkType: deterministic
- autofix: no

Для контентной области в 8 колонок или модальных окон меньше `1140 px` рекомендуется использовать 2 колонки данных.

#### Правильно

```text
Модальное окно 960 px -> 2 колонки данных
```

#### Неправильно

```text
Модальное окно 960 px -> 5 колонок данных
```

#### Почему

Слишком много колонок в узком контексте ухудшает сравнение и ломает читаемость.

### Rule 5: Используй Vertical для островков и Mobile Web

- ruleId: rule:components.table-view.vertical-context
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

`Vertical` располагает данные в одну колонку, а основное значение выделяет большим кеглем. Используйте этот вид для островков и экранов Mobile Web.

#### Правильно

```text
Островок с ключевыми условиями -> Vertical
```

#### Неправильно

```text
Островок с узкой шириной -> Horizontal multi-column
```

#### Почему

Вертикальный вид лучше работает в узких областях и на мобильных экранах.

### Rule 6: Ограничивай количество строк по умолчанию

- ruleId: rule:components.table-view.default-visible-rows
- severity: warning
- appliesTo: component
- checkType: manual
- autofix: no

Определите, сколько строк показывать по умолчанию, а остальные спрячьте под действие `Ещё N`.

#### Правильно

```text
Показаны 5 строк, остальные скрыты под «Ещё 8»
```

#### Неправильно

```text
Все 20 строк показаны сразу в компактном блоке
```

#### Почему

Ограничение строк удерживает компонент компактным и не перегружает страницу.

### Rule 7: Не скрывай один лишний пункт

- ruleId: rule:components.table-view.no-single-hidden-row
- severity: recommendation
- appliesTo: component
- checkType: deterministic
- autofix: no

Если всего 6 пунктов, показывайте все 6 без кнопки `Ещё N`.

#### Правильно

```text
Всего 6 строк -> показаны все 6
```

#### Неправильно

```text
Показаны 5 строк и кнопка «Ещё 1»
```

#### Почему

Кнопка ради одного скрытого пункта добавляет лишнее действие и не экономит значимое пространство.

### Rule 8: Пиши действие раскрытия по контексту данных

- ruleId: rule:components.table-view.more-link-context
- severity: warning
- appliesTo: text
- checkType: llm
- autofix: partial

Текст ссылки зависит от данных: используйте `Ещё N` или контекстный вариант вроде `Ещё N организаций`. В раскрытом состоянии используйте `Свернуть`.

#### Правильно

```text
Ещё 5 организаций
Свернуть
```

#### Неправильно

```text
Показать больше
Скрыть данные назад
```

#### Почему

Контекстная ссылка сразу объясняет, какие данные пользователь раскроет.

### Rule 9: Отключай divider в последней строке, если после таблицы нет элементов

- ruleId: rule:components.table-view.last-row-divider
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: partial

Если после таблицы нет элементов, отключите divider в последней строке. Правило актуально только для многоколоночной горизонтальной таблицы.

#### Правильно

```text
Horizontal multi-column, таблица последняя в блоке -> divider последней строки выключен
```

#### Неправильно

```text
Horizontal multi-column, после таблицы ничего нет -> divider последней строки включён
```

#### Почему

Лишний divider в конце создаёт визуальный хвост и выглядит как незавершённый блок.

### Rule 10: Описывай тип данных в первой колонке через Caption

- ruleId: rule:components.table-view.first-column-caption
- severity: error
- appliesTo: text
- checkType: llm
- autofix: partial

Первая колонка через `Caption` описывает тип данных в строке. Если требуется расшифровка, добавьте `Info`-иконку.

#### Правильно

```text
Caption: Тип документа
Title: Паспорт РФ
```

#### Неправильно

```text
Caption: Паспорт РФ
Title: Тип документа
```

#### Почему

Пользователь сначала должен понять тип параметра, а затем прочитать значение.

### Rule 11: Сохраняй один тип данных в Title-колонках

- ruleId: rule:components.table-view.title-columns-same-data-type
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

В таблице с несколькими колонками тип данных в колонках `Title` должен совпадать.

#### Правильно

```text
Колонка 1 Title: имя сотрудника
Колонка 2 Title: имя сотрудника
```

#### Неправильно

```text
Колонка 1 Title: имя сотрудника
Колонка 2 Title: дата
```

#### Почему

Одинаковый тип данных в колонках позволяет сравнивать значения сверху вниз.

### Rule 12: Добавляй общий заголовок для пояснения группы колонок

- ruleId: rule:components.table-view.additional-header
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Если нужно пояснение в нескольких колонках, добавьте дополнительную строку с общим заголовком.

#### Правильно

```text
Дополнительный заголовок: Порода
Колонки: Аляскинский маламут, Бретонский эпаньоль
```

#### Неправильно

```text
Пояснение продублировано в каждой колонке.
```

#### Почему

Общий заголовок снижает повтор и помогает понять группу данных.

### Rule 13: Выноси групповые действия в RightAddon блока TitleView

- ruleId: rule:components.table-view.group-actions-titleview
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Групповые действия с ячейками выносите в правый аддон со ссылкой в блоке `TitleView`.

#### Правильно

```text
TitleView RightAddon: ссылка на групповое действие
```

#### Неправильно

```text
Одно и то же групповое действие повторяется в каждой ячейке.
```

#### Почему

Групповое действие относится ко всему блоку, поэтому должно быть рядом с заголовком, а не дублироваться в строках.

## Section 7: Шаблоны

### Horizontal compact

```text
Контекст: 8 колонок, модальное окно или сайд-панель до 800 px
Данные: одна колонка
Линия чтения: слева направо по каждой строке
```

### Horizontal multi-column

```text
Контекст: несколько колонок данных
Линия чтения: сверху вниз
Рекомендация для 8 колонок или модалки < 1140 px: 2 колонки данных
```

### Vertical

```text
Контекст: островок или Mobile Web
Данные: одна колонка
Главное значение: выделено большим кеглем
```

### Раскрытие строк

```text
Показать по умолчанию: N строк
Скрытые строки: Ещё N [тип данных]
Раскрытое состояние: Свернуть
```

### Первая колонка

```text
Caption: тип данных
Info: опционально, если нужна расшифровка
Title / Subtitle: значение
```

## Section 8: Примеры

### Пример 1: Компактная горизонтальная таблица

```text
Тип документа -> Паспорт РФ
Серия и номер -> 6780 678390
Дата выдачи -> 21.06.2005
```

Подходит для одной колонки данных в форме, модальном окне или сайд-панели.

### Пример 2: Многоколоночная таблица

```text
Команда «Ностромо»
Артур Даллас -> Работает -> 27 февраля 2075
Томас Кейн -> На больничном -> 20 апреля 2083
```

Подходит для поиска и сравнения значений по нескольким колонкам.

### Пример 3: Вертикальная таблица

```text
Сумма
50 000 000 ₽
Срок
36 месяцев
```

Подходит для островка или Mobile Web, где данные идут в одну колонку.

### Пример 4: Раскрытие строк

```text
Показаны 5 строк
Ещё 7 организаций
Свернуть
```

Текст раскрытия уточняет тип скрытых данных.

## Section 9: Антипримеры

### Антипример 1: Multi-column в узкой области

```text
Side panel 760 px -> 5 колонок данных
```

В узкой области используйте компактный или вертикальный вид.

### Антипример 2: Кнопка ради одного скрытого пункта

```text
Показаны 5 строк
Ещё 1
```

Если всего 6 строк, показывайте все 6.

### Антипример 3: Несовпадающие типы данных в Title-колонках

```text
Колонка 1 Title: имя сотрудника
Колонка 2 Title: дата оформления
```

В многоколоночной таблице `Title`-колонки должны описывать один тип данных.

### Антипример 4: Групповое действие в каждой ячейке

```text
Каждая строка содержит одну и ту же ссылку «Скачать всё».
```

Групповое действие нужно вынести в `RightAddon` блока `TitleView`.

### Антипример 5: Последний divider без следующего элемента

```text
Последняя строка multi-column таблицы завершена divider, после таблицы ничего нет.
```

Если таблица последняя в блоке, divider последней строки отключается.

## Section 10: Машинная обработка

### Детерминированные проверки

- Проверять, что `Horizontal :: compact` не используется шире рекомендованного контекста без причины.
- Проверять, что в модальном окне меньше `1140 px` для `Horizontal :: multi-column` используется не больше двух колонок данных.
- Проверять, что в `Horizontal :: multi-column` последняя строка без следующего элемента не содержит divider.
- Проверять, что при 6 строках не используется кнопка `Ещё 1`.
- Проверять наличие `Свернуть` в раскрытом состоянии.
- Проверять, что групповые действия находятся в `TitleView RightAddon`.

### Словарные проверки

- Находить неконтекстные тексты раскрытия: `Показать больше`, `Раскрыть`, `Скрыть данные назад`.
- Находить рекомендуемые формулы `Ещё N`, `Ещё N организаций`, `Свернуть`.
- Находить подписи первой колонки, которые выглядят как значение, а не тип данных.

### LLM-проверки

- Проверять, что выбранный вид `TableView` соответствует линии чтения и контексту.
- Проверять, что `Vertical` используется для островков и Mobile Web.
- Проверять, что в многоколоночной таблице `Title`-колонки описывают один тип данных.
- Проверять, что дополнительные заголовки объясняют группу колонок, а не дублируют значения.
- Проверять, что `Info`-иконка в первой колонке нужна для расшифровки, а не добавлена без причины.

### Не проверяется автоматически

- Финальное продуктово обоснованное количество строк по умолчанию.
- Удобство сравнения конкретного набора данных без макета.
- Редакторское качество текста в `Info`-подсказке.
- Корректность визуальной иерархии главного значения в `Vertical`.
- Уместность группового действия в конкретном бизнес-сценарии.

### Автоисправления

- Заменить `Показать больше` на `Ещё N`, если известно количество скрытых строк.
- Заменить кнопку `Ещё 1` на показ всех 6 строк, если всего строк 6.
- Убрать divider последней строки в `Horizontal :: multi-column`, если после таблицы нет элементов.
- Перенести повторяющееся групповое действие в `TitleView RightAddon`, если действие относится ко всему блоку.
- Добавить `Свернуть` для раскрытого состояния.
