## Section 1: Определение

`Table Wide [D]` - десктопная широкая таблица для сценариев Альфа-Бизнеса, где пользователю нужно работать с большим набором колонок, настраивать их видимость, порядок и ширину, сортировать данные, закреплять колонки, выбирать строки и выполнять групповые действия.

В настройках таблицы широкая версия включается через параметр `Расширенный вид`. Для проектирования такого состояния используется компонент `Table :: Wide`.

## Section 2: Когда использовать

Используйте `Table Wide [D]`, когда таблица:

- содержит много колонок и требует горизонтальной прокрутки;
- должна давать пользователю настройку видимости, порядка и ширины колонок;
- содержит сортируемые колонки;
- требует закрепления колонок при горизонтальном скролле;
- содержит больше `10` строк и нуждается в пагинации;
- поддерживает выбор строк и групповые действия;
- группирует строки разделителями по дате, компании или контрагенту;
- размещается как самостоятельный табличный блок в теле `CorporateContent`.

## Section 3: Когда не использовать

Не используйте `Table Wide [D]`, если достаточно простой базовой таблицы без горизонтального скролла, закрепления колонок и расширенных настроек.

Не используйте `TableView` вместо `Table Wide [D]`, если пользователю нужны полноценные табличные сценарии: сортировка, настройка колонок, пагинация, выбор строк или bulk actions.

Не используйте отдельный компонент `TableBulkActions` в новой сборке таблиц: групповые действия должны включаться через состояние пагинационного блока.

## Section 4: Принципы

1. `Расширенный вид` переводит таблицу из базового состояния в широкое.
2. Пользователь может скрывать колонки, но не может скрыть последнюю видимую колонку.
3. Порядок колонок меняется через drag-and-drop в списке настроек.
4. `Сбросить всё` возвращает видимость, порядок и ширину колонок к базовым значениям.
5. Шеврон настроек колонки доступен в каждой колонке.
6. Сортировка показывается только там, где колонка действительно сортируемая.
7. Закрепление колонок доступно в широкой таблице и недоступно в базовой.
8. Ширина колонки должна учитывать заголовок, addon, сортировку и `ColumnControl`.
9. Пагинация включается по объёму данных, а не как декоративный блок.
10. При bulk actions используется режим `BulkActions` пагинационного блока.

## Section 5: Структура текста

Заголовки колонок должны кратко называть данные. Если колонка сортируемая, заголовок связывается с состоянием `Sorting`: `Not selected`, `Min -> Max` или `Max -> Min`.

Разделители строк подписываются конкретной группировкой. Для даты пишите день и месяц; колонку даты можно оставить, если по ней нужна сортировка. Для группировки по компании пишите название компании или контрагента.

Дополнительные индикаторы и слоты используются после лейбла или в конце строки: иконка, счётчик, статус или другой согласованный addon.

## Section 6: Правила

### Rule 1: Используй Table Wide для расширенного вида

- ruleId: rule:components.table-wide-d.use-wide-component
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Если в настройках таблицы включён `Расширенный вид`, таблица должна быть собрана на компоненте `Table :: Wide`.

#### Правильно

```text
Расширенный вид: on -> Table :: Wide
```

#### Неправильно

```text
Расширенный вид: on -> Table Basic
```

#### Почему

Широкая таблица содержит нужные состояния для горизонтального скролла, настройки колонок, закрепления и bulk actions.

### Rule 2: Не скрывай последнюю видимую колонку

- ruleId: rule:components.table-wide-d.keep-one-visible-column
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В настройках можно отключать отображение любых колонок, кроме последней видимой.

#### Правильно

```text
В таблице осталось две видимые колонки. Пользователь может скрыть одну из них.
```

#### Неправильно

```text
Пользователь может скрыть единственную оставшуюся колонку.
```

#### Почему

Таблица без видимых колонок теряет смысл и не может отобразить данные.

### Rule 3: Давай менять порядок колонок в настройках

- ruleId: rule:components.table-wide-d.column-order-drag-and-drop
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Порядок колонок меняется drag-and-drop в списке доступных колонок. После изменения порядок в таблице должен совпадать со списком настроек.

#### Правильно

```text
Колонка «Дата» перетащена наверх списка -> в таблице она стоит перед «Компания».
```

#### Неправильно

```text
Порядок в настройках изменён, но таблица осталась в прежнем порядке.
```

#### Почему

Настройки должны напрямую управлять структурой таблицы.

### Rule 4: Сбрасывай настройки к базовому состоянию

- ruleId: rule:components.table-wide-d.reset-all-restores-baseline
- severity: error
- appliesTo: flow
- checkType: deterministic
- autofix: no

Кнопка `Сбросить все настройки` возвращает видимость, порядок и ширину колонок к базовым значениям.

#### Правильно

```text
Нажатие «Сбросить всё» восстановило исходные колонки, порядок и ширины.
```

#### Неправильно

```text
Нажатие «Сбросить всё» восстановило только видимость колонок.
```

#### Почему

Сброс должен быть полным и предсказуемым для пользователя.

### Rule 5: Не скрывай ColumnControl в заголовке

- ruleId: rule:components.table-wide-d.column-control-visible
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

`ColumnControl` в `[D] HeadCell` должен быть видимым и доступным клиенту. Его нельзя скрывать из-за ширины колонки или визуального упрощения.

#### Правильно

```text
Title + Sorting + ColumnControl помещаются в заголовке колонки.
```

#### Неправильно

```text
ColumnControl скрыт, потому что колонка узкая.
```

#### Почему

Через `ColumnControl` пользователь открывает настройки конкретной колонки.

### Rule 6: Показывай сортировку только у сортируемых колонок

- ruleId: rule:components.table-wide-d.sorting-only-for-sortable-columns
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Если колонка сортируемая, в меню колонки доступны сортировка по возрастанию и убыванию. Если колонка не сортируемая, пункты сортировки в меню не показываются.

#### Правильно

```text
Сортируемая колонка -> Sort ascending, Sort descending
Несортируемая колонка -> Pin column, Reset column width
```

#### Неправильно

```text
Несортируемая колонка содержит пункты Sort ascending и Sort descending.
```

#### Почему

Меню должно показывать только действия, которые можно выполнить с конкретной колонкой.

### Rule 7: Используй закрепление только в широкой таблице

- ruleId: rule:components.table-wide-d.pinning-wide-only
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Закрепление колонки доступно в `Table Wide [D]`. В базовой таблице закрепление не используется, потому что у неё нет горизонтального скролла.

#### Правильно

```text
Table Wide -> Pin column доступен
Table Basic -> Pin column отсутствует
```

#### Неправильно

```text
Table Basic показывает действие Pin column.
```

#### Почему

Закрепление нужно только там, где пользователь прокручивает таблицу по горизонтали.

### Rule 8: Давай сброс ширины одной или всех колонок

- ruleId: rule:components.table-wide-d.column-width-reset
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: no

Если ширину колонок можно менять вручную, меню колонки должно позволять сбросить ширину текущей колонки и ширины всех колонок.

#### Правильно

```text
Меню колонки содержит Reset column width и Reset width of all columns.
```

#### Неправильно

```text
Ширину можно изменить, но сбросить её нельзя.
```

#### Почему

Пользователь должен иметь способ вернуться к базовым ширинам после ручной настройки.

### Rule 9: Включай пагинацию при количестве строк больше 10

- ruleId: rule:components.table-wide-d.pagination-by-row-count
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: no

Если в таблице `10` строк или меньше, блок с одной страницей можно отключить через preset `None`. Если появляется вторая страница, включайте preset `Pagination`.

#### Правильно

```text
10 строк -> Pagination: None
25 строк -> Pagination
```

#### Неправильно

```text
25 строк показаны без пагинации.
```

#### Почему

Пагинация нужна для управления большим объёмом строк, а не для имитации нижней панели.

### Rule 10: Делай нижний блок sticky при переполнении

- ruleId: rule:components.table-wide-d.sticky-plate-when-overflow
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Если таблица не помещается во вьюпорт по высоте, нижний блок пагинации или bulk actions должен работать как sticky plate и оставаться у нижнего края видимой области таблицы.

#### Правильно

```text
Строки скроллятся под sticky plate, пагинация остаётся видимой.
```

#### Неправильно

```text
Пагинация уезжает вниз и недоступна без прокрутки до конца таблицы.
```

#### Почему

Управление страницами и выбранными строками должно оставаться доступным в длинной таблице.

### Rule 11: Используй BulkActions в блоке пагинации

- ruleId: rule:components.table-wide-d.bulk-actions-use-pagination-preset
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Если в таблице есть чекбоксы и пользователь выбирает строку, нижний блок переключается в режим групповых действий через preset `BulkActions`. В новой сборке таблиц не используйте отдельный компонент `TableBulkActions`.

#### Правильно

```text
Выбрана строка -> pagination block preset: BulkActions
```

#### Неправильно

```text
Выбрана строка -> добавлен отдельный TableBulkActions.
```

#### Почему

Групповые действия являются состоянием нижнего блока таблицы и должны работать вместе с пагинацией.

### Rule 12: Оборачивай самостоятельную таблицу в BackgroundPlate

- ruleId: rule:components.table-wide-d.background-plate-wrapper-in-content
- severity: error
- appliesTo: screen
- checkType: deterministic
- autofix: no

При размещении `Table Wide [D]` как самостоятельного блока в теле `CorporateContent` таблица должна быть вложена в `[D] BackgroundPlate` первого уровня через `[D] BackgroundPlateSlot`.

#### Правильно

```text
CorporateContent -> BackgroundPlate Level 1 -> BackgroundPlateSlot -> Table Wide [D]
```

#### Неправильно

```text
CorporateContent -> Table Wide [D]
```

#### Почему

Обёртка задаёт корректный фон и отступы табличного блока внутри продуктовой страницы.

## Section 7: Шаблоны

### Широкая таблица

```text
Table :: Wide
HeadRow :: Universal
BodyRow :: Wide
Pagination / BulkActions
```

### Настройки колонок

```text
Вид таблицы: Расширенный
Столбцы:
- Компания
- Дата
- Сумма
Сбросить всё
```

### Меню сортируемой колонки

```text
Sort ascending
Sort descending
Pin column
Reset column width
Reset width of all columns
```

### Меню несортируемой колонки

```text
Pin column
Reset column width
Reset width of all columns
```

## Section 8: Примеры

### Пример 1: Скрытие колонок

```text
Пользователь скрывает колонку «Дата».
В таблице остаются «Компания», «Сумма» и «Статус».
```

Сценарий допустим, потому что в таблице остаются видимые колонки.

### Пример 2: Закрепление

```text
Пользователь закрепляет колонку «Компания».
Колонка «Компания» и все колонки слева остаются фиксированными при горизонтальном скролле.
```

Закрепление работает в `Table Wide [D]`, где есть горизонтальная прокрутка.

### Пример 3: Bulk actions

```text
Пользователь выбирает строку через checkbox.
Нижний блок переключается в BulkActions.
```

Групповые действия остаются частью пагинационного блока.

## Section 9: Антипримеры

### Антипример 1: Wide-сценарий собран на Basic

```text
Включён «Расширенный вид», но используется Table Basic.
```

Такой компонент не покрывает закрепление, горизонтальную прокрутку и настройки широкой таблицы.

### Антипример 2: Скрыт ColumnControl

```text
Заголовок колонки показывает только текст, ColumnControl скрыт.
```

Пользователь теряет доступ к настройкам колонки.

### Антипример 3: Отдельный TableBulkActions

```text
Под таблицей добавлен отдельный TableBulkActions.
```

В новой сборке таблиц bulk actions должны включаться через preset нижнего блока.

### Антипример 4: Нет пагинации при большом количестве строк

```text
В таблице 40 строк, но блок пагинации отключён.
```

Пользователь не получает управляемой навигации по данным.

## Section 10: Машинная обработка

### Детерминированные проверки

- Проверять, что `Расширенный вид` использует `Table :: Wide`.
- Проверять, что нельзя скрыть последнюю видимую колонку.
- Проверять видимость `ColumnControl` в `[D] HeadCell`.
- Проверять, что меню несортируемой колонки не содержит действий сортировки.
- Проверять, что `Pin column` не используется в базовой таблице.
- Проверять наличие reset-действий для ширины колонок.
- Проверять, что при количестве строк больше `10` используется pagination-состояние.
- Проверять, что bulk actions включаются через preset `BulkActions`, а не через `TableBulkActions`.
- Проверять обёртку самостоятельной таблицы в `[D] BackgroundPlate` первого уровня.

### Словарные проверки

- Определять группировки по дате, компании и контрагенту в разделителях строк.
- Определять названия колонок, где сортировка обычно уместна: дата, сумма, статус, компания.
- Определять технические названия старого компонента `TableBulkActions`.

### LLM-проверки

- Проверять, что выбранный набор колонок соответствует сценарию.
- Проверять, что порядок колонок после drag-and-drop логически совпадает с настройками.
- Проверять необходимость sticky plate по высоте таблицы и видимой области.
- Проверять уместность addon, индикаторов и счётчиков в строках.

### Не проверяется автоматически

- Реальная бизнес-логика сортировки данных.
- Корректность серверной пагинации.
- Причина выбора конкретной начальной сортировки.
- Удобство набора колонок в конкретном сценарии.

### Автоисправления

- Автоисправление не применяется для выбора компонента и сценарной логики.
- Можно предложить заменить `TableBulkActions` на preset `BulkActions` нижнего блока.
- Можно предложить включить `ColumnControl`, если слой скрыт.
- Можно предложить добавить `[D] BackgroundPlate` первого уровня для самостоятельной таблицы.
