## Section 1: Определение

Редактируемый `TitleView` — сценарий использования заголовка страницы, в котором пользователь может изменить информацию, содержащуюся в заголовке.

Паттерн фиксирует два варианта: редактируется весь заголовок или редактируется только часть заголовка. Он также описывает обязательность `Subtitle` для полностью редактируемого заголовка, сценарии редактирования номера и даты, а также адаптивное поведение.

## Section 2: Когда использовать

Используйте редактируемый `TitleView`, когда:

- название объекта задаёт пользователь;
- в заголовке нужно изменить номер, дату или другой динамический фрагмент;
- пользователь редактирует название шаблона, счёта, платежа или похожего объекта;
- без редактирования в заголовке сценарий становится длиннее или менее очевидным;
- заголовок должен сохранить компонентную структуру `TitleView`.

## Section 3: Когда не использовать

Не используйте редактируемый `TitleView`, если:

- заголовок является статичным названием раздела или продукта;
- значение нельзя редактировать пользователю;
- редактируемое поле лучше расположить в форме как обычный input;
- изменение заголовка не влияет на объект или сценарий;
- редактируемость можно понять только из подсказки, но не из самого элемента управления.

Не превращайте любой заголовок страницы в редактируемый только ради сокращения формы.

## Section 4: Принципы

1. Редактируемость должна быть привязана к реальному пользовательскому действию.
2. Есть два варианта: редактируется весь заголовок или редактируется часть заголовка.
3. Если редактируется весь заголовок, `Subtitle` обязателен.
4. `Subtitle` объясняет, что находится на экране, когда название изменено пользователем.
5. Если редактируется часть заголовка, статичная часть остаётся видимой.
6. Для редактирования даты используется иконка календаря.
7. Редактируемый заголовок не должен занимать больше одной строки без сокращения.
8. В адаптиве affordance редактирования должен оставаться доступным.
9. Редактирование не должно ломать иерархию `TitleView`.
10. Для базовой структуры, размеров и слотов применяется паттерн `TitleView`.

## Section 5: Структура текста

Полностью редактируемый заголовок:

```text
Title: <редактируемое название объекта>
Subtitle: <тип объекта или смысл экрана>
```

Частично редактируемый заголовок:

```text
Title: <статичная часть> + <редактируемый фрагмент>
Subtitle: <дополнительное описание, если нужно>
```

Если редактируется только дата, рядом с редактируемым фрагментом используется иконка календаря. Если редактируется номер, в заголовке сохраняется статичная сущность, а номер выступает динамическим фрагментом.

## Section 6: Правила

### Rule 1: Используй редактируемый TitleView только для изменяемой информации

- ruleId: rule:components.title-view-editable.real-editable-value
- severity: error
- appliesTo: screen
- checkType: llm
- autofix: no

Редактируемый заголовок применяется только тогда, когда пользователю нужно изменить информацию, содержащуюся в заголовке.

#### Правильно

```text
Пользователь может изменить название шаблона платежа в TitleView
```

#### Неправильно

```text
Статичный заголовок раздела "Платежи" оформлен как редактируемый
```

#### Почему

Редактируемость должна обозначать действие. Если значение нельзя изменить, элемент создаёт ложное ожидание.

### Rule 2: Добавляй Subtitle при полностью редактируемом заголовке

- ruleId: rule:components.title-view-editable.full-title-subtitle-required
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

Если редактируется весь заголовок, к нему добавляется `Subtitle`, который описывает суть происходящего на экране.

#### Правильно

```text
Title: Мой шаблон
Subtitle: Шаблон рублёвого платежа
```

#### Неправильно

```text
Title: Мой шаблон
Subtitle отсутствует
```

#### Почему

После редактирования названия шаблона, счёта или другого объекта смысл экрана не должен теряться.

### Rule 3: Не дублируй редактируемое название в Subtitle

- ruleId: rule:components.title-view-editable.subtitle-entity-meaning
- severity: warning
- appliesTo: text
- checkType: llm
- autofix: partial

`Subtitle` должен объяснять тип объекта или контекст экрана, а не повторять изменённое пользователем название.

#### Правильно

```text
Title: Командировки
Subtitle: Шаблон платежа
```

#### Неправильно

```text
Title: Командировки
Subtitle: Командировки
```

#### Почему

Задача подзаголовка — сохранить смысл страницы после изменения названия.

### Rule 4: При частичном редактировании сохраняй статичную часть заголовка

- ruleId: rule:components.title-view-editable.partial-title-static-context
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

Если редактируется только часть заголовка, неизменяемая часть остаётся видимой и задаёт контекст редактируемого фрагмента.

#### Правильно

```text
Title: Рублёвый платёж N 123457
Редактируется только N 123457
```

#### Неправильно

```text
Title: N 123457
Пользователь не видит, что это номер платежа
```

#### Почему

Статичная часть помогает понять, какую сущность пользователь редактирует.

### Rule 5: Используй иконку календаря для редактирования даты

- ruleId: rule:components.title-view-editable.date-calendar-icon
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: partial

Если в заголовке редактируется только дата, используйте иконку календаря.

#### Правильно

```text
Title: Валютная операция от 07.01.2024
Editable part: 07.01.2024 + calendar icon
```

#### Неправильно

```text
Title: Валютная операция от 07.01.2024
Editable part: 07.01.2024 + generic edit icon
```

#### Почему

Календарь сразу показывает тип редактируемого значения и ожидаемый способ выбора даты.

### Rule 6: Используй частичное редактирование для номера или даты в заголовке

- ruleId: rule:components.title-view-editable.number-date-partial-edit
- severity: warning
- appliesTo: screen
- checkType: llm
- autofix: no

Когда нужно включить в заголовок номер или дату, используйте частичное редактирование, чтобы оставить тип объекта видимым.

#### Правильно

```text
Title: Расчётный документ N 12345 от 07.01.2024
Редактируется N 12345 или дата
```

#### Неправильно

```text
Title: 12345
Редактируется весь заголовок без контекста документа
```

#### Почему

Номер и дата сами по себе плохо объясняют объект. Статичная часть заголовка сохраняет контекст.

### Rule 7: Сокращай редактируемый заголовок после первой строки

- ruleId: rule:components.title-view-editable.single-line-ellipsis
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: partial

Редактируемый заголовок скрывается в ellipsis после первой строки.

#### Правильно

```text
Длинное название пользовательского шаблона...
```

#### Неправильно

```text
Длинное название пользовательского шаблона переносится на несколько строк и сдвигает контент страницы
```

#### Почему

Пользовательские названия непредсказуемы по длине. Однострочное сокращение защищает структуру заголовка и соседние слоты.

### Rule 8: Сохраняй affordance редактирования в адаптиве

- ruleId: rule:components.title-view-editable.adaptive-edit-affordance
- severity: error
- appliesTo: screen
- checkType: llm
- autofix: no

В адаптивной версии редактируемый фрагмент и способ запуска редактирования должны оставаться доступными.

#### Правильно

```text
Adaptive: Title сокращён, иконка редактирования или календаря остаётся доступной
```

#### Неправильно

```text
Adaptive: редактируемая иконка скрыта, изменить заголовок невозможно
```

#### Почему

Адаптив не должен убирать ключевое действие сценария.

### Rule 9: Не заменяй форму редактируемым заголовком без причины

- ruleId: rule:components.title-view-editable.no-form-replacement
- severity: warning
- appliesTo: screen
- checkType: llm
- autofix: no

Редактируемый `TitleView` не должен заменять поля формы, если редактирование относится не к названию, номеру, дате или другому компактному фрагменту заголовка.

#### Правильно

```text
Название шаблона редактируется в TitleView
Реквизиты платежа редактируются в форме
```

#### Неправильно

```text
Несколько реквизитов платежа редактируются через заголовок страницы
```

#### Почему

Заголовок подходит для коротких идентифицирующих значений, но не для сложного ввода.

### Rule 10: Сохраняй базовые правила TitleView

- ruleId: rule:components.title-view-editable.base-title-view-rules
- severity: error
- appliesTo: component
- checkType: llm
- autofix: no

Редактируемый заголовок должен сохранять базовую структуру `TitleView`: корректный размер, слоты, `Subtitle`, адаптивность и skeleton-состояние.

#### Правильно

```text
TitleView View=xLarge
Title: editable
Subtitle: Шаблон платежа
RightAddon: Link
```

#### Неправильно

```text
Редактируемый заголовок собран из отдельных текстовых слоёв и иконок вне TitleView
```

#### Почему

Редактируемость является сценарным поведением `TitleView`, а не поводом отказаться от компонентной структуры.

## Section 7: Шаблоны

### Полностью редактируемый заголовок

```text
TitleView View=xLarge
Title=<редактируемое название>
Subtitle=<тип объекта или смысл экрана>
```

### Частично редактируемый заголовок

```text
TitleView View=xLarge
Title=<статичная часть> + <редактируемый номер или дата>
Subtitle=<описание, если нужно>
```

### Редактирование даты

```text
TitleView
Title=<статичная часть> + <дата>
Editable part=<дата>
Icon=calendar
```

## Section 10: Машинная обработка

### Детерминированные проверки

- Проверять, что компонент относится к `[D] TitleView` или `[M] TitleView`.
- Проверять наличие редактируемого состояния или интерактивного фрагмента в заголовке.
- Проверять, что при полном редактировании `Title` присутствует непустой `Subtitle`.
- Проверять, что если редактируемый фрагмент распознан как дата, рядом используется calendar icon.
- Проверять, что редактируемый `Title` ограничен одной строкой и ellipsis.
- Проверять, что структура не собрана вручную из текстовых слоёв вне `TitleView`.

### Словарные проверки

- Находить даты в редактируемом фрагменте без calendar icon.
- Находить пустые или дублирующие `Subtitle` при полностью редактируемом заголовке.
- Находить generic edit icon рядом с датой.

### LLM-проверки

- Проверять, что редактируемый `TitleView` используется только для изменяемой пользователем информации.
- Проверять, что при частичном редактировании есть статичная часть `Title`.
- Проверять, что `Subtitle` объясняет тип объекта или смысл экрана.
- Проверять, что номер или дата не остаются без контекста объекта.
- Проверять, что в адаптивной версии редактируемый фрагмент и иконка не скрыты без альтернативы.
- Проверять, что правила базового паттерна `ptrn:components.title-view` остаются применимыми.

### Не проверяется автоматически

- Бизнес-право пользователя редактировать конкретное значение.
- Корректность названия объекта после пользовательского ввода.
- Полный сценарий сохранения, отмены и валидации редактирования.
- Уместность переноса поля из формы в заголовок без знания сценария.

### Автоисправления

- Добавить calendar icon к редактируемой дате, если дата и роль фрагмента распознаны однозначно.
- Включить one-line ellipsis для редактируемого `Title`.
- Предложить `Subtitle` из типа объекта, если он явно указан в макете или названии экрана.
