## Section 1: Определение

`Table Basic [D]` - базовый десктопный режим таблицы Arui-Private для простых табличных сценариев Альфа-Бизнеса с небольшим количеством данных.

Компонент используется, когда таблице не нужен горизонтальный скролл и не нужно закреплять столбцы. Для базовой таблицы рекомендуется использовать не более `5` столбцов.

## Section 2: Когда использовать

Используйте `Table Basic [D]`, когда таблица:

- содержит небольшой набор колонок;
- умещается в доступную ширину без горизонтального скролла;
- не требует закрепления столбцов;
- допускает настройку видимости, порядка и ширины колонок;
- содержит сортируемые колонки;
- может группировать строки через `GroupBar`;
- содержит чекбоксы и групповые действия;
- размещается как самостоятельный табличный блок в теле `CorporateContent`.

## Section 3: Когда не использовать

Не используйте `Table Basic [D]`, если таблице нужен широкий режим, горизонтальный скролл, закрепление столбцов или большое количество колонок. Для таких сценариев используйте `Table Wide [D]`.

Не используйте базовую таблицу как способ показать много данных в сжатом виде: если таблица требует больше `5` столбцов, проверьте переход в wide-сценарий.

Не используйте отдельный компонент `TableBulkActions` в новой сборке таблиц: групповые действия включаются через состояние пагинационного блока.

## Section 4: Принципы

1. Basic - это простой режим без горизонтального скролла.
2. Рекомендуемое количество столбцов - до `5`.
3. Закрепление столбцов в Basic недоступно.
4. Группировка по столбцам в Basic недоступна.
5. Группировка строк возможна через `GroupBar`.
6. Шеврон настроек столбца нельзя скрывать.
7. `ControlCell` и `ActionCell` нельзя удалять: если они не нужны, выбирайте preset `None`.
8. `HeaderRow` и `BodyRow` можно детачить для сборки локальных строк, остальные компоненты не детачатся.
9. Пагинация включается по количеству строк, а не как декоративный блок.
10. При bulk actions используется режим `BulkActions` пагинационного блока.

## Section 5: Структура текста

Заголовки колонок должны кратко называть данные и не конфликтовать с управляющими элементами шапки. Если заголовок или содержимое не помещается по ширине, текст скрывается через эллипсис.

Для суммы задавайте минимальную ширину по самому длинному значению, чтобы сумма не уходила в сокрытие.

Разделители `GroupBar` подписываются конкретной группировкой. Для даты пишите день и месяц; колонку даты можно оставить, если по ней нужна сортировка. Для группировки по компании пишите название компании или контрагента.

## Section 6: Правила

### Rule 1: Используй Basic для простых таблиц

- ruleId: rule:components.table-basic-d.use-basic-for-simple-table
- severity: recommendation
- appliesTo: component
- checkType: llm
- autofix: no

`Table Basic [D]` используйте для простой таблицы с небольшим количеством данных и без потребности в горизонтальном скролле.

#### Правильно

```text
5 столбцов, таблица помещается в ширину -> Table Basic [D]
```

#### Неправильно

```text
9 столбцов, нужна горизонтальная прокрутка -> Table Basic [D]
```

#### Почему

Basic рассчитан на простой режим отображения данных; wide-сценарии должны уходить в `Table Wide [D]`.

### Rule 2: Не включай горизонтальный скролл

- ruleId: rule:components.table-basic-d.no-horizontal-scroll
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В базовой таблице не бывает горизонтального скролла. Не включайте `Scrollbar` в блоке пагинации.

#### Правильно

```text
Table Basic [D] -> Pagination без Scrollbar
```

#### Неправильно

```text
Table Basic [D] -> Pagination со Scrollbar
```

#### Почему

Горизонтальный скролл относится к широкому режиму таблицы.

### Rule 3: Не закрепляй столбцы

- ruleId: rule:components.table-basic-d.no-column-pinning
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В `Table Basic [D]` недоступна функция закрепления столбца. Действие `Закрепить столбец` не должно появляться в меню.

#### Правильно

```text
Table Basic [D] -> меню колонки без «Закрепить столбец»
```

#### Неправильно

```text
Table Basic [D] -> меню колонки содержит «Закрепить столбец»
```

#### Почему

Закрепление нужно только в таблице с горизонтальным скроллом.

### Rule 4: Не используй группировку по столбцам

- ruleId: rule:components.table-basic-d.no-column-grouping
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В `Table Basic [D]` не реализован функционал группировки по столбцам. В настройках таблицы не показывайте управление `Группировать` для столбцов.

#### Правильно

```text
Table Basic [D] -> настройки столбцов без column grouping
```

#### Неправильно

```text
Table Basic [D] -> настройка «Группировать: Контрагенты»
```

#### Почему

Column grouping относится к другой логике таблицы; в Basic допустима только группировка строк через `GroupBar`.

### Rule 5: Используй GroupBar для группировки строк

- ruleId: rule:components.table-basic-d.group-rows-with-groupbar
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Для группировки строк в базовой таблице используйте `GroupBar`.

#### Правильно

```text
GroupBar: 28 декабря
GroupBar: АО «Тайрелл Технологии»
```

#### Неправильно

```text
Группировка строк оформлена как обычная строка BodyRow.
```

#### Почему

`GroupBar` визуально отделяет группы строк и не смешивается с данными таблицы.

### Rule 6: Не скрывай шеврон настроек столбца

- ruleId: rule:components.table-basic-d.column-settings-chevron-visible
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

У каждого столбца должен быть шеврон с выпадающим по клику списком настроек. Шеврон нельзя скрывать.

#### Правильно

```text
Каждый HeadCell содержит видимый Chevron настроек.
```

#### Неправильно

```text
В части колонок Chevron скрыт.
```

#### Почему

Через шеврон пользователь получает доступ к настройкам конкретного столбца.

### Rule 7: Не удаляй ControlCell и ActionCell

- ruleId: rule:components.table-basic-d.keep-control-and-action-cells
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Не удаляйте `ControlCell` и `ActionCell` из шапки и строк таблицы. Если в строке нет чекбоксов или кнопки действия, выбирайте preset `None` в `[D] BodyControlCell`, `[D] BodyActionCell`, `[D] HeadControlCell` и `[D] HeadActionCell`.

#### Правильно

```text
BodyControlCell preset: None
BodyActionCell preset: None
```

#### Неправильно

```text
BodyControlCell удалён из строки.
BodyActionCell удалён из строки.
```

#### Почему

Служебные ячейки сохраняют структуру строки и дополнительные отступы в начале и конце таблицы.

### Rule 8: Сбрасывай настройки к базовому состоянию

- ruleId: rule:components.table-basic-d.reset-all-restores-baseline
- severity: error
- appliesTo: flow
- checkType: deterministic
- autofix: no

Кнопка `Сбросить все настройки` возвращает видимость, порядок и ширину столбцов к базовым значениям.

#### Правильно

```text
Нажатие «Сбросить всё» восстановило исходные колонки, порядок и ширины.
```

#### Неправильно

```text
Нажатие «Сбросить всё» восстановило только порядок колонок.
```

#### Почему

Сброс настроек должен быть полным и предсказуемым.

### Rule 9: Показывай сортировку только у сортируемых колонок

- ruleId: rule:components.table-basic-d.sorting-only-for-sortable-columns
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Если колонка сортируемая, в меню доступны сортировка по возрастанию и убыванию. Если колонка не сортируемая, пункты сортировки в меню не показываются.

#### Правильно

```text
Сортируемая колонка -> Сортировать по возрастанию, Сортировать по убыванию
Несортируемая колонка -> Сбросить ширину столбца
```

#### Неправильно

```text
Несортируемая колонка содержит пункты сортировки.
```

#### Почему

Меню должно показывать только действия, которые доступны для конкретной колонки.

### Rule 10: Давай сброс ширины одной или всех колонок

- ruleId: rule:components.table-basic-d.column-width-reset
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: no

Если ширину колонок можно менять вручную, меню колонки должно позволять сбросить ширину текущей колонки и ширины всех колонок.

#### Правильно

```text
Сбросить ширину столбца
Сбросить ширину всех столбцов
```

#### Неправильно

```text
Ширину можно изменить, но сбросить её нельзя.
```

#### Почему

Пользователь должен иметь способ вернуться к базовым ширинам после ручной настройки.

### Rule 11: Включай пагинацию при количестве строк больше 10

- ruleId: rule:components.table-basic-d.pagination-by-row-count
- severity: warning
- appliesTo: component
- checkType: deterministic
- autofix: no

Если в таблице `10` строк или меньше, блок с одной страницей можно отключить через preset `None`. Если появляется вторая страница, включайте preset `Pagination`.

#### Правильно

```text
10 строк -> Pagination: None
95 строк -> Pagination
```

#### Неправильно

```text
95 строк показаны без пагинации.
```

#### Почему

Пагинация нужна для управления большим объёмом строк.

### Rule 12: Делай нижний блок sticky при переполнении

- ruleId: rule:components.table-basic-d.sticky-plate-when-overflow
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Если таблица не помещается во viewport по высоте, нижний блок пагинации или bulk actions должен работать как sticky plate.

#### Правильно

```text
Строки скроллятся под sticky plate, пагинация остаётся видимой.
```

#### Неправильно

```text
Пагинация доступна только после прокрутки до конца таблицы.
```

#### Почему

Управление страницами и выбранными строками должно оставаться доступным в длинной таблице.

### Rule 13: Используй BulkActions в блоке пагинации

- ruleId: rule:components.table-basic-d.bulk-actions-use-pagination-preset
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

Если в таблице есть чекбоксы и пользователь выбирает строку, нижний блок переключается в режим групповых действий через preset `BulkActions`. Не используйте отдельный компонент `TableBulkActions`.

#### Правильно

```text
Выбрана строка -> pagination block preset: BulkActions
```

#### Неправильно

```text
Выбрана строка -> добавлен отдельный TableBulkActions.
```

#### Почему

Групповые действия являются состоянием нижнего блока таблицы.

### Rule 14: Оборачивай самостоятельную таблицу в BackgroundPlate

- ruleId: rule:components.table-basic-d.background-plate-wrapper-in-content
- severity: error
- appliesTo: screen
- checkType: deterministic
- autofix: no

При размещении `Table Basic [D]` как самостоятельного блока в теле `CorporateContent` таблица должна быть вложена в `[D] BackgroundPlate` первого уровня.

#### Правильно

```text
CorporateContent -> BackgroundPlate Level 1 -> Table Basic [D]
```

#### Неправильно

```text
CorporateContent -> Table Basic [D]
```

#### Почему

Обёртка задаёт корректный фон, скругления и отступы табличного блока внутри продуктовой страницы.

### Rule 15: Не скрывай последнюю видимую колонку

- ruleId: rule:components.table-basic-d.keep-one-visible-column
- severity: error
- appliesTo: component
- checkType: deterministic
- autofix: no

В настройках можно отключать отображение любых колонок, кроме последней видимой.

#### Правильно

```text
В таблице осталось две видимые колонки. Пользователь может скрыть одну из них.
```

#### Неправильно

```text
Пользователь может скрыть единственную оставшуюся колонку.
```

#### Почему

Таблица без видимых колонок не может отобразить данные.

### Rule 16: Давай менять порядок колонок в настройках

- ruleId: rule:components.table-basic-d.column-order-drag-and-drop
- severity: warning
- appliesTo: component
- checkType: llm
- autofix: no

Порядок колонок меняется drag-and-drop в списке доступных колонок. После изменения порядок в таблице должен совпадать со списком настроек.

#### Правильно

```text
Колонка «Дата» перетащена наверх списка -> в таблице она стоит перед «Компания».
```

#### Неправильно

```text
Порядок в настройках изменён, но таблица осталась в прежнем порядке.
```

#### Почему

Настройки должны напрямую управлять структурой таблицы.

### Rule 17: Детачь только HeaderRow и BodyRow

- ruleId: rule:components.table-basic-d.detach-only-rows
- severity: error
- appliesTo: component
- checkType: manual
- autofix: no

Для сборки локальной конфигурации можно детачить строки `HeaderRow` и `BodyRow`. Остальные компоненты таблицы детачить нельзя.

#### Правильно

```text
Детачены HeaderRow и BodyRow, остальные компоненты остались инстансами.
```

#### Неправильно

```text
Детачены Pagination, HeadCell и BodyCell.
```

#### Почему

Детач только строк сохраняет компонентные контракты вложенных частей и позволяет собрать локальные `Local :: HeaderRow` и `Local :: BodyRow`.

## Section 7: Шаблоны

```text
CorporateTopbar
HeaderRow

```

### Меню сортируемой колонки

```text
Сортировать по возрастанию
Сортировать по убыванию
Сбросить ширину столбца
Сбросить ширину всех столбцов
```

### Меню несортируемой колонки

```text
Сбросить ширину столбца
Сбросить ширину всех столбцов
```

### Отключённые служебные ячейки

```text
HeadControlCell preset: None
HeadActionCell preset: None
BodyControlCell preset: None
BodyActionCell preset: None
```

## Section 8: Примеры

### Пример 1: Простая таблица

```text
Название компании
Дата
Номер счёта
Статус
Сумма
```

Пять столбцов помещаются в доступную ширину, поэтому подходит `Table Basic [D]`.

### Пример 2: Группировка по дате

```text
GroupBar: 28 декабря
BodyRow
BodyRow
GroupBar: 26 декабря
BodyRow
```

Строки сгруппированы через `GroupBar`, а не через column grouping.

### Пример 3: Нет действий в строке

```text
BodyControlCell preset: None
BodyActionCell preset: None
```

Служебные ячейки остаются в структуре строки и сохраняют отступы.

## Section 9: Антипримеры

### Антипример 1: Basic с горизонтальным скроллом

```text
Table Basic [D] + Scrollbar в пагинации
```

Горизонтальный скролл относится к wide-режиму.

### Антипример 2: Закрепление столбца

```text
Меню Table Basic [D] содержит «Закрепить столбец».
```

Закрепление не работает в базовой таблице.

### Антипример 3: Удалены служебные ячейки

```text
Из строки удалены BodyControlCell и BodyActionCell.
```

Нужно оставлять ячейки и выбирать preset `None`.

### Антипример 4: Отдельный TableBulkActions

```text
Под таблицей добавлен отдельный TableBulkActions.
```

В новой сборке таблиц bulk actions должны включаться через preset нижнего блока.

## Section 10: Машинная обработка

### Детерминированные проверки

- Проверять отсутствие horizontal scrollbar в `Table Basic [D]`.
- Проверять отсутствие действия `Закрепить столбец` в меню базовой таблицы.
- Проверять отсутствие column grouping в настройках Basic.
- Проверять видимость шеврона настроек в каждом столбце.
- Проверять наличие `ControlCell` и `ActionCell` в шапке и строках.
- Проверять использование preset `None` вместо удаления служебных ячеек.
- Проверять reset видимости, порядка и ширины колонок.
- Проверять, что нельзя скрыть последнюю видимую колонку.
- Проверять, что порядок колонок совпадает с порядком в настройках.
- Проверять, что при количестве строк больше `10` используется pagination-состояние.
- Проверять, что bulk actions включаются через preset `BulkActions`, а не через `TableBulkActions`.
- Проверять обёртку самостоятельной таблицы в `[D] BackgroundPlate` первого уровня.

### Словарные проверки

- Определять группировки по дате, компании и контрагенту в `GroupBar`.
- Определять техническое название старого компонента `TableBulkActions`.
- Определять пункты меню `Закрепить столбец`, `Сбросить ширину столбца` и `Сбросить ширину всех столбцов`.

### LLM-проверки

- Проверять, что сценарий действительно простой и не требует wide-режима.
- Проверять уместность количества столбцов в доступной ширине.
- Проверять необходимость sticky plate по высоте таблицы и видимой области.
- Проверять корректность подписей `GroupBar`.

### Не проверяется автоматически

- Факт детача конкретных Figma-инстансов, если Apollo не передаёт это как отдельное свойство.
- Реальная бизнес-логика сортировки данных.
- Корректность серверной пагинации.
- Причина выбора конкретной начальной сортировки.
- Удобство набора колонок в конкретном сценарии.

### Автоисправления

- Автоисправление не применяется для выбора режима таблицы и сценарной логики.
- Можно предложить заменить `TableBulkActions` на preset `BulkActions` нижнего блока.
- Можно предложить заменить удаление служебных ячеек на preset `None`.
- Можно предложить убрать `Scrollbar` и `Закрепить столбец` из Basic-сценария.
