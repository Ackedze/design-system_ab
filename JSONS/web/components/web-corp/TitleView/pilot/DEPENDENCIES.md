# Данные для вложенных компонентов TitleView

Статус: **reader существующих raw реализован локально; свежая полевая приёмка ожидается**. Публикация не выполняется.

Согласованная область: 16 вариантов TitleView Desktop/MobileWeb и 42 вложенных семейства. 27 служебных семейств проверяются по контракту/эталону владельца; используются 10 существующих основных контрактов и зависимость Spinner r8. Новые нормы и самостоятельные контракты служебных частей не вводятся.

## Результат сверки 04.11.2026

Настоящий V3 `parseNormalizedJsonCatalog` и `resolveStructure`, выполненные в памяти без записи файлов, восстановили **43 из 43 требуемых вариантов по всем 11 контрактам** из существующих `structure` + `variantStructures`. Получено 288 узлов; у всех 16 текстовых узлов есть шрифт и размер, у 14 есть style key. Отсутствие style key у остальных двух само по себе не доказывает пропуск экспорта.

В полном raw TitleView уже есть 130 узлов базового Desktop-варианта, включая скрытые. Стили, токены, таблицы режимов Font/Theme и цепочки aliases также имеются в существующих каталогах `JSONS/styles` и `JSONS/tokens`.

Контроль: настоящий V3 `diffStructures` обнаружил замену text style у Button Label с исходного 16–20 Component Primary на 18–24 Primary Large, используя исходный raw Button и значения Label из отчёта владельца. Остальные узлы оставлены равными для изоляции проверки; это не полный живой аудит TitleView.

Ранее объявленное требование отдельных native-эталонов было преждевременным: прежний reader требовал `nativeAuditFactsV1` и отклонял обычные каталоги до использования уже существующих полей. Отсутствие этого блока не равно отсутствию фактов. Дополнительные native-файлы и повторные выгрузки для базовой сверки пилота не требуются.

## Что переиспользовать

- Полные исходные каталоги выбранных компонентов и V3-сборку варианта из базового дерева и patches.
- `styles.*.styleKey`, `fillToken`, `strokeToken`, `typographyToken`, размеры, отступы, заливки, радиусы, эффекты и текстовые свойства.
- `componentInstance.componentKey` и `variantProperties` для вложенных компонентов; существующие контрактные факты для нормативных правил.
- Существующие style/token каталоги для устойчивых ключей, режимов и alias-цепочек. Не дублировать их у каждого узла.

## Точечные ограничения

В 43 проверенных вариантах не записаны Auto Layout direction/alignment/sizing, выравнивание текста, явные режимы экземпляров и подробные диапазоны смешанного текста. Public BOOLEAN/TEXT/SWAP wiring также не восстанавливается из одного variant name. Наличие отдельного каталога режимов не доказывает выбранный режим конкретного исходного экземпляра.

Проверки таких фактов требуют отдельного доказательства из уже имеющихся источников; без него конкретное условие остаётся UNKNOWN. Это не повод отклонять всё дерево, требовать полный новый native-снимок или выдавать неподтверждённое PASS. Поведение V3 нельзя копировать вслепую: например, наличие неизменного style ID само по себе не исключает inline-переопределение типографики.

## Локальная реализация

Apollo 0.4.5 использует raw-поля и V3 reader Proxy, без нового снимка или повторной выгрузки. Привязки вложений требуют подтверждённого parent/owner/family; одинаковые соседи не выбираются по порядку. Изменённый вариант допускает чтение типизированной настройки для правила применения, но не наследует baseline потомков старого варианта. На сохранённом отчёте обнаружены оба нарушения применения TitleView и изменение text style Button Label. Это replay прежних фактов, а не свежий запуск Figma. Данные не расширяются без доказанного конкретного пробела. Установку и ручные прогоны выполняет владелец.

Точный состав и текущие raw pins: [dependency-sources.json](dependency-sources.json). Контракты и ревизии остаются прежними. Исторические native-подготовки и seals не переписываются.
