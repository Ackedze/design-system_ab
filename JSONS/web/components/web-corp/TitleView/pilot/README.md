# TitleView: единый пилот двух источников эталона

Статус: контракт **r5**, автоматические контроли пройдены, свежая ручная приёмка владельцем ещё не выполнена. Совместимая поставка готовится как Apollo0.4.2 / Proxy1.4.17 / data1.4.17-data.20261103.1. Установку и ручной прогон выполняет владелец.

## Источники и объём

Исходный `../../Web _ Corp Components -- TitleView.json` уже содержит Desktop и MobileWeb. Он сохранён без изменений. `catalog.json` сохраняет все его 12 компонентов и структуры; только два TitleView дополнены `nativeAuditFactsV1`. Сопоставлены 16 вариантов: Desktop / MobileWeb × xLarge / Large / Medium / Small × Skeleton False / True.

Дополнительные поля связывают нативные ID и топологию, прямые API-привязки и опубликованные ключи ресурсов. Значения и alias токенов берутся из независимого источника. Визуальные значения проверяемого экземпляра не становятся эталоном. Для подготовки читались существующие master-компоненты; экземпляры не создавались, макет не менялся, Apollo в Figma не запускался. В обычной проверке библиотечный эталон должен читаться из пакета Proxy.

Контракт сохраняет прежние42 baseline/text условия и policy; r5 добавляет10 usage условий. Шесть ветвей Type взаимоисключающие, четыре Accent условия соответствуют четырём source occurrences. `test-cases.json` содержит 16 профилей, 84 положительных и 84 отрицательных контроля условий, 16 матриц BOOLEAN-настроек и семь проверок защиты/жизненного цикла. Для каждого индивидуального правила сохранены полный текст и стабильный RuleID; при создании кейса на холсте оба должны быть видимы.

Автоматически перебираются **3072 комбинации BOOLEAN-свойств** в 16 вариантах. Это конечная ось API, а не заявление о переборе любых текстов, swaps, шрифтов и комбинаций режимов. Точные условия и границы находятся в JSON.

## Воспроизводимая автоматическая подготовка

Нужны checkout Apollo с установленными devDependencies и актуальным `dist/runtime.cjs`, checkout Proxy и принятый корень данных `contracts` с `manifest.json`. Утилита использует существующие reader, материализатор и Predicate Engine; собственных правил сравнения нет. Пути передаются явно, папка workplace и аккаунт автора не требуются.

```sh
node '<design-system_ab>/JSONS/web/components/web-corp/TitleView/pilot/verify.cjs' \
  --apollo '<Apollo>' \
  --proxy '<apollo-proxy>' \
  --contracts '<принятый пакет>/contracts' \
  --output '<новый каталог результата>'
```

Команда проверяет исходные хеши, создаёт отдельный `contracts/` с обновлённым дескриптором каталога и сохраняет `BASE-CASES.json`, `RULE-CONTROLS.json`, `STATE-CONTROLS.json`, `RESULT.json`. Существующие контракты и остальные каталоги сохраняются. Выходной каталог должен быть новым. Его `contracts/` можно передать существующей сборке пакета данных как dataRoot. Команда не публикует данные, не меняет установленный Proxy и не запускает Figma.

Проверки строят синтетические фактические snapshots для контроля движка. Они не доказывают нативный захват или равенство с live-library. Полевое сравнение выполняется отдельно.

В группе отрицательных тестов стили меняются на другой стиль/отвязываются, а не на произвольную строку ID. Для strokeWeight добавить видимый stroke и изменить толщину: исходно при отсутствии обводки условие неприменимо. Для baseline-свойств без доступного редактирования экземпляра записать ограничение Figma, не detach всего компонента ради зелёного кейса. Для проверки прочих состояний выбирать нужный вариант на экземпляре, а не менять библиотечный master.

Остановку и повтор запускать на том же экземпляре. До нового результата предыдущий должен оставаться доступен. Выделение и слои не должны самопроизвольно перемещаться. Сначала проверять отдельные экземпляры; время всей TitleView-секции измерять отдельно от секции с другими компонентами.

Прислать парные JSON для одинаковых настроек OFF/ON, версию/сборку плагина, версии Proxy и данных, полное время первого и повторного запуска. Сравниваем verdict, RuleID/subject/trace, число проверенных компонентов и условий, UNKNOWN и ошибки. Быстрый ответ с нулём проверок не является ускорением.

## Незакрытое покрытие

- Исходные Skeleton-профили сейчас дают 19–21 human-review из-за доказательств targets/selectors в r4. Это не успех пилота и не ошибка отсутствующего MobileWeb raw. Нормы и engine не ослаблены ради устранения UNKNOWN.
- xLarge в обоих представлениях сохраняет один mixed-paint human-review.
- Прямой BOOLEAN→visible поддержан только при полной независимой топологии, совпавшем владельце и согласованных binding/reference. Сложный nested swap, смена вложенного варианта или неподтверждённая комбинация режимов остаются явным пробелом.
- Внешние dependencies/слоты не считаются полностью проверенными только из-за совпадения собственного оформления TitleView.
- Полевая приёмка прежнего TV-03 не распространяется на новые варианты и настройки.

## Новые usage проверки r5

`verify-usage.cjs --apollo /path/to/Apollo --output /new/output` проверяет16
исходных профилей, все6 Type на двух платформах, отрицательные и RESET состояния,
самостоятельный TitleStatus, missing Type, Accent/Primary и скрытую кнопку.
`verify.cjs` сохраняет отдельные84 проверки прежних42 baseline/text условий и
3072 конечные BOOL-проекции. Оба скрипта синтетические; это не native Figma PASS.

Кейс9103:61981 содержит импортированную старую версию библиотечного API. Перед
полевым сравнением r5 использовать отдельную копию и обновить экземпляр через
Figma, затем повторить намеренные Type/Accent/типографические изменения. Real
API drift не маскируется portable-ID нормализацией и остаётся UNKNOWN.
