# Пилот суммы и подтверждения для Figma и фронта

Дата: 5 октября 2026 года. Задача G01 выполнена фиксацией этого сценария и [решения о размещении модулей](GENERATION-PLACEMENT.md). Документ определяет входы и ожидания будущей сборки; Figma-макет и приложение на этом этапе ещё не созданы.

Связанные документы: [план генерации](GENERATION-PLAN.md), [action points](GENERATION-ACTIONS.md).

## Цель и область пилота

Из одного общего плана создать контентную область CorporateContent с суммой, пояснением и действием подтверждения. Проверить наполнение Body, зависимости AmountStyles → Amount и Button → Spinner, соответствие содержания и loading в Figma и фронте.

Поверхность пилота — содержимое CorporateContent, а не полная продуктовая страница. Header, SideMenu, Section, формы ввода, Modal и ButtonsGroup в первую сборку не включаются. Сценарий содержит одно действие; ButtonsGroup добавляется отдельным кейсом после первой приёмки.

Desktop и mobile-web проверяются в светлом оформлении на viewport 1600 × 900 и 375 × 812 соответственно. Это условия демонстрации. Оболочка CorporateContent получает соответствующий grid mode и разрешённый page background mode по своим фактам и mappings; ручные замены её защищённых paddings, grid style и оформления не задаются.

## Входные данные и тексты

| Поле | Значение |
| --- | --- |
| Идентификатор сценария | `amount-confirmation` |
| Язык | `ru-RU` |
| Подпись суммы | `Сумма к подтверждению` |
| Пояснение | `Проверьте сумму и подтвердите действие` |
| Подпись действия | `Подтвердить` |
| Сумма в минимальных единицах | `125050` |
| Валюта | `RUB` |
| Количество дробных знаков | `2` |
| Числовой смысл | `1250.50 RUB` |
| Знак операции | Не показывается |
| Дробная часть и валюта | Показываются |
| Addon суммы | Выключен |

Минимальные единицы задают точное значение без арифметики с плавающей точкой. Отображение Major — `1 250` с математическим пробелом U+205F, Minor — `,50`, Currency — штатный вариант `₽`. Основание группировки — правило `rule:components.amount.math-space` в паттерне Amount; запятая подтверждена редакционными правилами чисел.

Это ожидание частей суммы и числового смысла. Одинаковая буквальная конкатенация всех Figma TEXT и DOM textContent не требуется: штатное расстояние до Currency может обеспечиваться layout компонента. Общие примеры редполитики содержат U+202F; для Major этого компонентного пилота выбрано явное правило Amount с U+205F. Выбор фиксируется в спецификации запуска и не изменяет источники правил.

## Состав и настройки

| Роль | Источник | Настройка пилота |

| Контейнер desktop | CorporateContent r12 | Desktop representation, Body наполнен планом |
| Контейнер mobile-web | CorporateContent mobile-web r7 | Mobile representation, сохранены системные TopMargin и BottomMargin |

| Сумма mobile-web | AmountStyles r10 | Профиль `headline-mobile`, `Style=Headline 16/20`, Operation выключен |
| Части суммы | Закреплённый Core Amount r5 | Major/Minor/Currency из входов, Addon выключен, Opacity=False у Minor и Currency по правилам пресета |
| Действие | Button r31 | Ordinary surface, Primary, Size 56, Rectangular, Hint выключен, SingleIcon=False |
| Загрузка действия | Закреплённый Spinner r8 | Один видимый Spinner в LeftAddon, Size 24, Inverted=True, Static=False |
| Подпись суммы | Каталог Web Typography | Paragraph Primary Medium, style key `f0f0d59f9f92db92901605dd929cfa3b93540058` |
| Пояснение | Каталог Web Typography | Paragraph Primary Small, style key `6fb5ab6969beee7da9e23dfcbab2f4864b30b665` |

Подпись и пояснение являются простыми текстовыми ролями содержимого Body. В Figma используются импортированные DS text styles и variable-bound цвета; на фронте — соответствующий проверенный Typography API. TitleView для этого локального блока не требуется. Наличие ключа в каталоге фиксирует источник; возможность live import и кодовое отображение проверяются в F01 и W01.

Все текстовые части суммы сохраняют единый стиль пресета и общий разрешённый цветовой токен. Цвет Addon в этой сборке не участвует, поскольку Addon выключен. В исходном профиле Operation включен; отключение здесь является явным решением сценария через разрешённый API, а не изменением профиля контракта.

## Композиция и независимые ожидания

В Body размещается одна вертикальная группа: подпись, сумма, пояснение и действие. Выравнивание по левому краю. Пользовательский структурный контейнер прозрачен и растёт по содержимому; защищённые свойства CorporateContent сохраняются.

Для этой fixture выбраны Spacing/16 между подписью, суммой и пояснением и Spacing/24 перед действием. Это условия пилота, основанные на существующих токенах, а не новое общее правило ДС. Figma keys: `59ff0616087ba120b5ba63514ac2699c634960e4` и `f7b969edbf5d6f8d732bf46ef7fd3f7c5511fb49`.

| Ожидание | Desktop | Mobile-web |
| --- | --- | --- |
| Ширина группы содержимого | Fill доступного Body | Fill доступного Body |
| Ширина действия | Fixed 240 px, выбранное условие fixture | Fill доступного контейнера |
| `block` | False | True |
| `textResizing` | Hug | Fill |
| `nowrap` | True | False |
| `constrainedWidth` | True | True |
| Пояснение | Перенос допустим | Перенос допустим |
| Высота содержимого | По содержимому | По содержимому |

Эти входы сохраняются до генерации и передаются проверяющему контуру независимо от actual. На mobile текст Button получает допустимое отображение Fill/Auto height/Center по контракту. Числовой размер 240 px не подменяет grid ширину оболочки и не переносится на мобильный вариант.

Цвет подписи и суммы — DS `text/primary`, key `53f842b1771349c5dca692351edfc422e8f081b5`; пояснение — DS `text/secondary`, key `d9d26239617e3ab9e69d7ed378d811a3c4561063`. На фронте соответствующие токены подтверждаются W01. Ручные RGB значения не являются результатом выбранного оформления.

## Состояния и события

| Состояние | Содержимое | Действие |
| --- | --- | --- |
| `ready` | Исходные подпись, сумма и пояснение | Видимый Label `Подтвердить`, Spinner и addons скрыты |
| `loading` | Сумма и пояснение сохраняются | Только один Spinner в LeftAddon; Label и Hint скрыты Boolean API, второй Addon скрыт |
| Возврат в `ready` | Исходные данные сохраняются | Label снова виден, Spinner скрыт |

Переход: `ready → confirm → loading → demoComplete → ready`. В приложении `demoComplete` наступает через 1000 ms; в автоматизированной проверке таймер управляется виртуальными часами. Повторное `confirm` во время loading игнорируется, счётчик принятого действия не увеличивается. Endpoint и реальная отправка не задаются.

У Button при переходе сохраняются View, Size, Shape, Disabled, SingleIcon, Colors и значения Label/Hint. Внутренний текст Label не очищается, меняется его видимость. Намерение loading хранится в общем плане: в Figma оно реализуется композицией Addon.Type=Spinner, а не несуществующим Figma-свойством Loading. На фронте используется подтверждённое отображение loading API; доступное имя действия сохраняется даже при скрытой визуальной подписи.

В Figma создаются представления ready и loading для демонстрации. Для проверки сохранения ширины отдельно фиксируется последовательная пара одного и того же instance в одной сессии при неизменных внешних условиях. Два разных нарисованных экземпляра не заменяют эту пару. Figma prototype transition не является обязательным результатом первой сборки.

## Критерии проверки

| ID | Проверка | Ожидаемый результат |
| --- | --- | --- |
| PILOT01 | Обе среды используют одну версию плана и одни данные | `1250.50 RUB`, одинаковые подписи и действие |
| PILOT02 | Содержимое Body | Созданные узлы сопоставлены с планом; library placeholder не выдаётся за содержимое |
| PILOT03 | Настройка суммы | Minor и Currency видимы, Operation и Addon скрыты; типографика и opacity удовлетворяют пресету |
| PILOT04 | Начальное действие | Primary/56/Rectangular, видимый Label, без Hint и addons |
| PILOT05 | Loading | Один Spinner24, Inverted=True/Static=False, нет видимых Label/Hint/второго Addon |
| PILOT06 | Ширина при переходе Figma | Разница ширины того же instance не больше 0.01 px по контракту Button |
| PILOT07 | Ширина при переходе фронта | Действие сохраняет layout при неизменном viewport; точный допуск браузерного измерения фиксируется в W03 отдельно от Figma-предиката |
| PILOT08 | Повторное действие | Во время loading не запускается второй цикл подтверждения |
| PILOT09 | Завершение демонстрации | Через управляемые 1000 ms возвращается ready, сумма не изменяется |
| PILOT10 | Доступность фронта | Действие доступно с клавиатуры, сохраняет имя и сообщает состояние busy подтверждённым API |
| PILOT11 | Адаптация | На 1600 и 375 отсутствует непредусмотренное горизонтальное переполнение; мобильная кнопка заполняет доступную ширину |
| PILOT12 | Пустой Body | Контрольный пустой сценарий сохраняет пустой native SLOT и корректную оболочку |
| PILOT13 | Запрещённый override | Целенаправленная правка защищённого свойства даёт нарушение и ссылку на RuleID |
| PILOT14 | Отсутствующие факты | Missing identity/reference/transition не считается успешной проверкой |

PILOT IDs обозначают сценарные ожидания, а не новые нормативные RuleID компонентов. Проверки компонентных норм используют существующие RuleID. Готовность генератора подтверждается на этапе I02; этот документ фиксирует заранее заданные результаты.

## Источники пилота

Компонентные нормы берутся из выбранных ZIP в этой папке. Их текущие revisions и hashes указаны в [снимке плана](GENERATION-PLAN.md#снимок-исходных-пакетов); G02 уже реализован в Apollo V4 и закрепляет фактические файлы в lock каждого запуска. При следующем run проверяется его собственный lock, а не исторический снимок G01.

Контекст применения и оформления дополнительно выбран из того же `design-system_ab`:

- `patterns/p_amount_component.md`: применяются monetary-values-only, math-space, optional-parts, fixed-part-order и same-text-style-for-parts в области пресета; правила таблиц, steps и side-panel к пилоту не относятся.
- `patterns/p_buttons-and-buttons-group.md`: action-verb и desktop-safe-variants; правила расположения нескольких действий здесь не применяются.
- `JSONS/styles/Web _ Typography.json`: два text style для подписи и пояснения.
- `JSONS/tokens/Spacing.json`: интервалы пользовательского содержимого.
- `JSONS/tokens/001 _ Interface Dynamic Colors.json`: источники text/primary и text/secondary.
- `redpolrules/llm_numbers_context.json` и `redpolrules/llm_currency_semantic.json`: десятичная запятая и показ валютного символа рядом с числом.

Эти источники не подменяют актуальные компонентные нормы ZIP. Полный паттерн CorporatePage не применяется к локальной контентной области. Штатные защитные свойства и режимы оболочки определяются её контрактом и evidence.

## Условия начала исполнения

G01 определяет сценарий и размещение. Следующие этапы отдельно проверяют схему плана, доступность live Figma import, действительность code mappings и исполнимость capture. Конкретный writable файл Figma выбирается перед F01; отсутствие этого файла сейчас не требует выдумывать node ID. Фронтовой preview размещается в выбранном приложении пилота, описанном в решении о размещении.

Критерий завершения G01: входы, тексты, роли, источники, независимые layout ожидания, state transition и критерии проверки заданы; места реализации общего ядра и обоих адаптеров определены. Этот критерий выполнен документацией, без заявления об исполнении генерации.
