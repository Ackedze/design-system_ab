# Тестовая сборка CorporateContent

Дата: 2 октября 2026 года.

[Открыть оба экрана в Figma](https://www.figma.com/design/I3MsagXR8Tz2eZcGtIgUk8/?node-id=13265-24492)

Собран сценарий «Обратная связь» в двух версиях: desktop 1600 × 900 и mobile-web 375 × 812. В каждой форме три поля и группа из двух действий. Desktop использует Header, SideMenu и Section с сеткой 8/4; mobile-web — AppHeaderTop и внешние подписи полей. Второстепенный справочный островок скрыт в мобильной версии.

CorporateContent и все продуктовые элементы сохраняют связь с опубликованными компонентами. Содержимое размещено в нативных Body и BackgroundPlateSlot; detach не использовался.

## Проверка

- CorporateContent: **34/34 предиката выполнены** — 17 на desktop и 17 на mobile-web.
- Оба Body подтверждены как границы ответственности вызывающей композиции.
- Эталонные узлы сопоставлены полностью: 2/2 desktop и 6/6 mobile-web.
- На каждом экране один главный TitleView, три Input Size=56, две Button Size=56; Primary стоит первой.
- Отступы формы: padding 32, интервалы полей 24, от заголовка до содержимого и от содержимого до действий 32.
- Desktop сохраняет ширины 824/400 и gutter 24; вложенных явных переключений desktop-сетки нет.
- Продуктовый текст использует Alfa Interface Sans. Переполнений текста не обнаружено; содержимое помещается в оба viewport.
- Визуально проверен итоговый снимок [screens.png](screens.png).

## Находки по вложенным контрактам

1. **Автоматическая проверка Button неполна.** ZIP загружен со всеми evidence-файлами и зависимостью Spinner. Снимки четырёх кнопок сопоставлены с независимыми эталонами их вариантов. Однако engine не подтверждает часть semantic targets, rule scope и зависимых фактов: 54 human-review на каждую desktop-кнопку и 49 на каждую mobile-web-кнопку. Остальные оценки — not-applicable. Эти результаты **не считаются успешным предикатным аудитом Button**. Визуальная и структурная проверки выбранных вариантов выполнены отдельно.
2. **Источники расходятся по интервалу мобильной группы.** Штатный [M] ButtonsGroup имеет effective baseline gap=8, тогда как общий паттерн формы указывает 16. Сборка сохраняет защищённый библиотечный baseline; изменение источников правил требует отдельной синхронизации.

## Файлы доказательств

- `report.json` — итоги, ID узлов и SHA-256 исходных ZIP.
- `captures.json` / `evaluation.json` — независимые снимки CorporateContent и результаты engine.
- `assembly-readback.json` — чтение сборки с учётом последующих правок текста и навигации.
- `button-captures.json` / `button-evaluation.json` — снимки и неполные оценки Button.
- `button-import-notes.json` — сведения о загрузке полного пакета Button.

Сборка проверяет генерацию макета в Figma. Логика отправки формы и публикация Code Connect в этот тест не входят. Следующий технический шаг — выяснить, почему semantic targets Button не подтверждаются на актуальных вариантах, и согласовать gap мобильного ButtonsGroup с паттерном формы.
