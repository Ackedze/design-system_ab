# Amount — компонентный контракт, r2

Статус на 29.09.2026: **Draft / не опубликован / исправления Editor проверены офлайн,
ожидается короткий live-прогон 0.2.55**.
Компонент `core.web.amount`, Figma `Amount` из Web _ Core. Не AmountInput и не
корпоративная композиция AmountStyles. Корневой ключ:
`fe3399f71c9e0971646821d935b64657e462c28e`.

## Что загрузить и что редактировать

В ComponentContract Editor **0.2.55 или новее** импортировать
[`editor/Amount.editor-input.zip`](editor/Amount.editor-input.zip).
ZIP содержит manual и Athena evidence; пересборка при импорте использует общий core.
Не импортировать соседний старый `../compiled/component-contract.v2.json`.

После обновления перезапустите Editor и повторно импортируйте ZIP r2. В r1 ключ
одиночного Amount ошибочно был также записан как `componentSetKey`: автоматическое
создание preview отклонялось, даже при правильном компоненте. Это ошибка пакета,
не выбор пользователя на холсте. Amount и Major сопоставляются по `componentKey`,
Minor и Currency — по реальным Component Set. R1 сохранён в
[`../history/r1-editor-0.2.53/`](../history/r1-editor-0.2.53/).

Единственный ручной нормативный источник — [`contract.manual.json`](contract.manual.json).
Сохраняйте изменённый manual из Editor, затем пересобирайте пакет. `compiled/`,
`evidence/`, `reports/`, `projections/`, `runtime/` и ZIP генерируются; их не редактируют.
`sources/` — закреплённые read-only копии исходных документов с SHA-256.
Проекции не опубликованы в ds-ai-hub/Athena. Паттерны не входят в компонентный runtime.

## Подтверждённые факты и текущая проверка

Свежая read-only выгрузка библиотеки: 29.09.2026, пять компонентов/23 варианта
(Amount, Major, Minor, Currency, Addon). Все 23 структуры доступны; корневое API
Amount — только BOOLEAN `Minor`, `Currency`, `Addon`, без root variants.
Major обязателен; остальные части опциональны. Вложенные TEXT/VARIANT редактируются
через их собственные свойства. `Operation`, `Negative` и `Size` на корне отсутствуют.

r2 содержит 23 записи правил: 20 исполняемых → 35 RuleIR и три явных разрешения
`policy-only`. Восемь записей порядка — одна смысловая норма для восьми комбинаций
видимости, не восемь разных требований дизайн-системы.

- Проверяются происхождение Amount и видимых Major/Minor/Currency по ключам,
  обязательный Major, согласованность BOOLEAN и фактической видимости частей,
  порядок видимых частей и независимый baseline оформления/Auto Layout корня.
- Разрешены смена Text Style и изменение размеров вслед за текстом/типографикой.
  Default font size и ширина не становятся универсальной нормой.
- `Opacity=True` в вариантах Minor/Currency не запрещён самим Core Amount.
  AB-запреты сохранены с прежними RuleID во внешнем
  [`pattern handoff`](../../../../patterns/amount/README.md), который пока не исполняется.
- Отсутствие reference, неверный ключ, неоднозначное сопоставление или truncated
  capture не превращаются в успешную полную проверку.

В Editor 0.2.53 исправлена общая диагностика: явное ложное условие на корне может
сделать правило скрытой части неприменимым. Пустой selector сам по себе этого не
доказывает. Predicate Engine остался единым интерпретатором; нового Amount runtime нет.

## Что ещё НЕ подтверждено

Матрица внутренних ручных styles/token overrides, допустимое наполнение Addon,
исполняемый контроль текста Currency только при Type=Custom, code value/minority
и фронтовая валидация. См. [`BACKLOG.md`](BACKLOG.md).
Полная проверка конкретного снимка означает исполнение **заявленных** правил r2,
а не исчерпывающую готовность всего контракта или разрешение любых непроверяемых правок.

## Проверка и воспроизводимость

Из корня design-system_ab:

```sh
node scripts/build_component_contract_reference.js experiments/web-core/core/Amount/authoring
node --test scripts/tests/amount-contract.test.js
```

Обычная сборка сохраняет pinned sources, проверяет их hash и не переписывает manual.
Обновление источников — отдельное осознанное действие `--refresh-sources` после
сверки фактов и обновления manual sourceHash, не автоматическая перегенерация норм.

19 офлайн-тестов покрывают все восемь visibility-комбинаций, 36 комбинаций
Currency/Opacity без продуктового запрета, позитивные/негативные структурные случаи,
неполные данные, воспроизводимость, ZIP roundtrip и неизменность старого runtime.
Дополнительно проверены standalone preview/selected-instance capture с настоящим
ZIP в plugin VM, отсутствие искусственного set key и отказ для чужих/неизвестных
ключей. Общий compiler выдаёт ошибку `STANDALONE_COMPONENT_AS_SET`, если pinned
Athena evidence доказывает, что указанный как set объект — одиночный компонент.
Generated evidence не переписано; старое имя группирующего поля в Athena v1
нормализуется только при доказанном совпадении component key и singleton evidence.
Это синтетические снимки и VM-проверки на закреплённых фактах, **не live-отчёты Figma**.
План live-прогона — [`TESTCASES.md`](TESTCASES.md).

### Исправление P0: Editor 0.2.55, тот же manual r2

Общий core теперь разрешает короткое имя свойства только в однозначный
типизированный Figma ID (с учётом API reference). Точные stale IDs не подменяются,
raw facts не нормализуются на месте. Semantic facts и availability используют
общий resolver. После доказанной независимым host reference смены nested variant
восстанавливается semantic target только его корня; дочерние цели и разрешения на
их изменение этим не наследуются.

Повторный расчёт18 сохранённых снимков:

- A02–A14C:14 корректных примеров, complete=true, inconclusive=0, нарушений нет.
- A15: gap нарушает baseline. A16: скрытый Major нарушает обязательность и уже
  существующее требование состава/порядка видимых частей. Обе проверки полные.
- A17A/B: подмены не проходят; остаются28 human-review в каждом, complete=false.
  Нормальная классификация7 условий порядка восстановлена, структурный remap — P1.

Это **новый расчёт старых raw facts**, не новые live-отчёты из Figma. Исходные
экспорты0.2.54 неизменны. Export JSON нового Editor и повторное исполнение проверены.
Manual, compiled, input ZIP, RuleID, generated facts и продуктовые границы не менялись.

Typecheck и473 Editor tests проходят, включая29 новых регрессий;244 Button,
27 доступных Spinner и19 Amount package tests тоже проходят. Два исторических
Spinner suites не запускаются из-за удалённых исходных JSON; они не засчитаны.
Amount synthetic fixtures теперь сохраняют #propertyId и актуальный capture profile.

QA: [`reports/binding-fix-0.2.55.2026-09-29.json`](reports/binding-fix-0.2.55.2026-09-29.json).
Воспроизведение: `node scripts/review_amount_binding_fix.js` из корня репозитория.
Далее перезапустить Editor и проверить короткий набор на прежнем стенде, см.
[`TESTCASES.md`](TESTCASES.md). Пересоздавать экземпляры или менять пакет не требуется.

### Первый live-прогон r2 / Editor 0.2.54

Получены 18 отчётов A02–A17B. Их hashes проверены; повторное вычисление engine,
Editor diagnostics и деталей полностью совпало во всех случаях (630 evaluations).
Исправление импорта одиночного Amount подтверждено. **Все 18 проверок неполные**:
`notExecuted=0` не означает успех, поскольку остаются `human-review`/inconclusive.

- A15: gap 0 → 8 правильно даёт нарушение baseline; A16: скрытый Major правильно
  даёт `major-required`. В 14 положительных кейсах ложных violations нет, но принять
  их нельзя до устранения неопределённых проверок.
- В обычном экземпляре 14 проверок неопределённы: manual использует пути
  `component.properties.Minor/Currency/Addon`, а реальные факты содержат
  `Minor#72085:2`, `Currency#72085:3`, `Addon#100902:0`. Общий semantic/availability
  слой делает точный lookup и не связывает эти имена с идентификаторами Figma.
- При допустимой смене Opacity (A12) либо Currency (A13/A14B/A14C) независимый
  эталон вложенного варианта найден, lineage подтверждён, но semantic target
  остаётся изолированным. Поэтому неопределённых проверок уже 18 либо 16.
- Подмены A17A/B не получают ложный pass: явная неполнота, 35 human-review и
  0/9 сопоставленных baseline-узлов. Это безопасный отказ, **не точное обнаружение
  нарушения identity**. Возникают два sibling Major с одинаковым ключом без
  INSTANCE_SWAP port; matcher отвергает неоднозначное сопоставление целиком.
- По A18A/B подтверждений отказа до запуска проверки пока нет; они не приняты.

Зелёные синтетические тесты не закрывают эти дефекты: их fixture убирает суффиксы
`#propertyId` и не включает `instanceIdentityVersion=1`, используемый live capture.
Выявленный P0 — общий resolver свойств, доказуемая привязка целей при nested variant
и регрессии на реальных snapshots; не новые ограничения самого Amount и не
ослабление identity gates. Первый разбор не менял реализацию; исправление0.2.55
и его отдельная QA зафиксированы выше.

Доказательства: [`reports/live-review-r2.2026-09-29.json`](reports/live-review-r2.2026-09-29.json).
Исходные JSON сохранены без изменений в `reports/fixtures/r2-editor-0.2.54/*.json.gz`
с SHA-256; удаление пользовательских экспортов из `editor/` не потеряет регрессию.
