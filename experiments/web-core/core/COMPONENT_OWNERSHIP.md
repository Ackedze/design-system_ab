# Границы владения контрактами — решение 2026-09-26

## Принято

- **Контракт компонента** описывает собственное API, реальные доступные состояния,
  внутренние инварианты, разрешённые способы изменения и зависимости.
- **Контракт родителя** задаёт ограничения конкретного места встраивания.
  Button выбирает Spinner и разрешённые для Loading параметры, но не копирует
  правила внутреннего устройства Spinner.
- **Паттерн использования** владеет ограничениями продукта/канала и композиции
  нескольких компонентов. Они не становятся универсальными запретами core API.
  Указание Product в проверке само по себе не переносит ownership в компонент.
- Generated facts read-only; единственный ручной нормативный источник каждого
  компонента — `contract.manual.json`. Compiled JSON и проекции пересобираются.
- Отсутствие контракта зависимости, недоказанная identity, неоднозначное место
  вложения или неполные факты дают неполную проверку, а не pass/эвристическое совпадение.
- Ограничения пересекаются, а не перезаписывают друг друга. Внешний контекст не
  ослабляет intrinsic-правило зависимости. Несовместимость — явный конфликт.

## Порядок Spinner → Button

1. **Собственный Spinner**: изолированный manual, исходные снимки, generated facts,
   общий compiler/Predicate Engine, ZIP для Editor и тесты. Результат — проверяемый
   Draft, а не обещание полной готовности Figma/code.
2. **Приёмка Spinner**: 12 вариантов, устранённые source gaps, правильные и
   намеренно изменённые instance, явные unknown, сохранность токенов; JSON-отчёты.
3. **Зависимость Button**: ссылка на `core.web.spinner` и revision/hash, точная
   lineage через Addon `Type=Spinner` (не glyph swap). Размер и View-матрица
   нормативны только в Button manual. Для каждого сочетания нужны факты,
   непроверенные сочетания не достраиваются по догадке.
4. **Общее исполнение**: compiler/runtime разрешают зависимость по стабильному ID
   и хешу, исполняют её собственные правила плюс ограничения родителя. Нужен
   общий маршрут fixed nested component, не Button-specific ветка и не копия
   predicates Spinner в Button. Missing/cycle/version/conflict → coverage gap.
5. **Приёмка Loading**: выбран правильный компонент/вариант, нет дублей Spinner,
   стили вложенного Spinner проверены его контрактом, ширина Button сохранена
   только при наличии независимого pre-loading reference. Снимок одного состояния
   не доказывает переход во времени.
6. **Продуктовые политики**: перенести ownership в паттерны с сохранением RuleID
   и crosswalk. Не удалять действующие ограничения до появления исполняемого
   маршрута pattern→component; разделить intrinsic coverage и usage coverage.
