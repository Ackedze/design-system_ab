# Навыки Apollo

Этот каталог в `design-system_ab` — единственный редактируемый источник инструкций
и профилей навыков Apollo. Известные исполнители — `apollo.layer-names`
и `apollo.landing` (совместимость прежних лендингов). Общий исполнитель новых
навыков генерации — `apollo.figma-mcp`.
Лендинги используют прямой CLI → Figma MCP и пакетный reader Proxy;
плагин предоставляет чат и контекст. UI, модели и логика сессии остаются в Apollo
и Proxy; файлы из каталога не добавляют исполняемый код.

## Структура

- `manifest.json` — сгенерированный индекс пакетов с хешами их описаний.
- `<skill-id>/manifest.json` — ID, версия пакета, название, описание, известный
  executor ID и сгенерированные pins заявленных файлов.
- `<skill-id>/SKILL.md`, `profile.json` — основные правила и профиль.
- `<skill-id>/run/SKILL.md`, `run/profile.json` — инструкция агентского цикла
  и её профиль совместимости.

`figma-layer-name-hygiene` сохраняет прежние четыре файла профилей.
`ab-generate-custom-landing` поставляет короткий SKILL.md, четыре тематических
документа `references/rules/` (бриф и композиция, выбор компонентов, контент
и ассеты, изменения), а также Figma workflow, контракт прогона и адаптер Proxy.
При старте загружается только SKILL.md; остальные документы читаются адресно
по текущему этапу. Вложенная папка `references/rules/` сохраняет совместимость
с текущим форматом пакета. Локальный Python helper остаётся в исходниках
для Codex и не исполняется из пакета данных Proxy.
Добавление папки навыка само по себе не добавляет карточку или native-возможности.
Метаданные каталога и README не передаются модели: запуск читает инструкции
только выбранного навыка.

## Новые навыки генерации

Для форм, других страниц и свободной композиции из компонентов используется один
исполнитель Figma MCP. В совместимой версии Apollo/Proxy селект «Что генерируем»
получает доступные навыки из установленного пакета; отдельная ветка Proxy под
каждый навык не нужна. Формы и остальные будущие навыки не считаются реализованными
лишь из-за наличия этого интерфейса подключения.

Папка нового навыка содержит `SKILL.md`, нужные `references/*.md` или `*.json` и
описание `manifest.json` следующего вида (pins пересчитывает штатный сборщик):

```json
{
  "schemaVersion": "apollo.skill-package.v2",
  "id": "your-generation-skill",
  "version": "1.0.0",
  "name": "Название в селекте",
  "description": "Назначение и область навыка",
  "executorId": "apollo.figma-mcp",
  "files": [
    {"path": "SKILL.md", "sha256": "<sha256 текста>", "bytes": 0}
  ],
  "generation": {
    "platforms": ["desktop"],
    "requiredResources": ["knowledge/data/ds-ai-hub/products/ab/manifest.json"],
    "initialQueries": ["products/ab/components/"],
    "initialFiles": ["SKILL.md"],
    "hostInstructions": "Указать специфичные инструкции сборки и чтения источников.",
    "workflow": "direct-cli-mcp-v1"
  }
}
```

ID соответствует имени папки; версия в metadata `SKILL.md` совпадает с manifest.
Список обязательных источников содержит точные ID установленного пакета.
`ds-ai-hub/AGENTS.md` читается исполнителем независимо от профиля. Нормы остаются
в документации компонентов/паттернов, а не копируются в manifest. Initial files
выбирают загружаемые сразу инструкции, остальные references доступны адресно.
Профиль не разрешает shell, сторонние endpoints или произвольные записи: границы
root, ownership, подтверждение результата и Stop определены общим исполнителем.

Сборщик обнаруживает все папки с manifest, проверяет формат/paths/хеши и включает
заявленные файлы в пакет. Скрипты из исходника навыка в поставку не попадают.
Новые названия и инструкции затем приходят через обновление данных. Для другого
исполнителя или платформы нужна совместимая доработка кода.

Перед первой публикацией v2 нужны совместимые Apollo/Proxy и runtime с capability
`figma-mcp-skills-v1`; новый runtime получает отдельный канал. Не включать v2
в канал401 прежних приложений. Активный landing использует `direct-cli-mcp-v1`; прежние
профили сохраняются для чтения истории и не возобновляются текущим runtime. Пример выше — описание формата, не готовый навык.

## Изменение и публикация

1. Редактировать инструкции здесь. При изменении инструкции обновить версию
   соответствующего профиля и его pin текста, затем версию пакета в его manifest.
   Профили сохраняют прежние wire/adapter/protocol pins; их изменение требует
   отдельно совместимого установленного кода.
2. Из принятого checkout `apollo-proxy` выполнить:

   ```sh
   node scripts/build-skill-catalog.js \
     --source /path/to/design-system_ab/apollo/skills \
     --runtime /path/to/installed-proxy/runtime/apollo \
     --index /path/to/design-system_ab/apollo/data-packages/current.json
   ```

   Команда проверяет оба профиля на принятом runtime, пересчитывает pins индекса
   и пакета и обновляет только поле `skills` общего Git-индекса. Контрактный
   snapshot, его dataId и runtimeId не меняются. Невалидный профиль не публикуется.
3. Сохранить каталог и обновлённый `apollo/data-packages/current.json` одним
   Git-коммитом и опубликовать его по действующему порядку. При публикации новых
   контрактов сохранять поле `skills`; повторный вызов команды связывает его
   с текущим состоянием каталога.
4. Штатное обновление знаний Proxy получает индекс, описание пакета и заявленные
   файлы из одного разрешённого Git commit. Отдельный digest навыков обнаруживает
   изменения даже при прежнем dataId; контрактный архив тогда не скачивается.
   Локальные знания сохраняются. Ошибка проверки оставляет текущий пакет;
   прежний пакет доступен штатному откату данных.

Для первой установки этой доставки требуется обновлённый Git data updater.
В дальнейшем изменения инструкций приходят через данные без новой сборки
плагина, изменения исполняющего кода или переустановки приложения.

Для первого подключения лендингов требуются совместимые код Apollo/Proxy,
portable runtime с Figma workflow и пакет данных с `apollo.landing`. Порядок
работы: «Генерация → Новый чат → Лендинг», бриф, существенные вопросы,
поэтапная сборка и правка секции. Установленный Proxy читает поставку,
без checkout на компьютере дизайнера. Публикация кода и данных выполняется
отдельно от Git push. Наличие manifest не означает выполненный реальный прогон.

## Копии совместимости

`Apollo/skills/figma-layer-name-hygiene` и
`apollo-proxy/src/skills/figma-layer-name-hygiene-run` сохраняются как замороженные
fallback для прежних поставок. Они больше не являются источником авторинга
или новой публикации. Установленные копии и локальная копия Codex также
не редактируются как независимые исходники.

Доставка сохраняет старые пути `skills/figma-layer-name-hygiene/` и
`skills/figma-layer-name-hygiene-run/`; вложенная папка `run/` относится к структуре
исходников. Поэтому переход не меняет формат запросов и выполнение навыка.
