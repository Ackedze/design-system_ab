# Лейаут Desktop-лендинга на отдельной странице

Применяй этот рецепт после [брифа](brief.md) и [композиции](composition.md), до сборки каркасов. Он относится к Desktop-лендингу на отдельной странице; для модального окна и Mobile Web этот рецепт не применяется. Компонент Section для лендингов не используй.

Технические операции выполняй по [Figma workflow](../figma-workflow.md). Системные настройки, токены и рецепты компонентов берутся из установленного Hub.

## Параметры

| Параметр | Правило |
|---|---|
| Ширина макета | Целевая ширина страницы, определённая в брифе или выбранном макете |
| Контейнер содержимого | Один `[D] CorporateContent` |
| Область размещения блоков | `[D] Body` внутри CorporateContent |
| Сетка | Режим `[D] Grid & Cols`, соответствующий ширине макета |
| Колонки, боковые поля и gutter | Переменные выбранного режима сетки |
| Размеры CorporateContent | Ширина Fill, высота Hug |
| Фон страницы | Mode `BackgroundPlate Color`; по умолчанию `base-bg-alt (grey)` |

Например, в подтверждённом режиме `1352` ширина 12 колонок составляет `1248`, боковые поля — `52`, gutter — `24`. Эти значения приходят из переменных, а не назначаются вручную; другой целевой ширине соответствует её режим сетки.

Различай ширину viewport и внутренней области контента. Ширина контента сама по себе не определяет Compact: применимость и настройки проверяй по рецепту конкретного компонента.

## Последовательность сборки

1. **Подготовь внешний лейаут.** Определи ширину страницы и выбери соответствующий режим сетки. Внешний Auto Layout-каркас оставь прозрачным; его высота должна увеличиваться вместе с содержимым. Сохрани выбранные ширины, modes, поверхности и интервалы со ссылками на их источники.

2. **Добавь CorporateContent.** Импортируй `[D] CorporateContent` и сохрани его библиотечные связи, системные размеры, поля и привязки. Фон задавай через `BackgroundPlate Color`. Оформление первого экрана не определяет фон всей страницы.

3. **Подготовь Body.** Найди `[D] Body` и удали его штатную неизменённую заглушку `SwapMe` по `products/ab/components/corporate-content/cookbook/02-desktop.md` установленного Hub. Сохрани сам контейнер и слот. Все блоки лендинга добавляй внутрь Body; пользовательское содержимое при продолжении работы сохраняется.

4. **Размести блоки в основном потоке.** Каркас Desktop-страницы задан ниже. Состав и порядок содержательных блоков определяются брифом, [композицией](composition.md) и паттерном лендингов. PromoMainBlock используется один на весь лендинг; Benefits располагается первым в основном контенте, Footer — последним.

   ```text
   [D] CorporateContent
   └── [D] Body
       ├── [D] PromoMainBlock
       ├── [D] Benefits
       ├── Контентные блоки по задаче лендинга
       └── 🔒 [D] Footer — View=Page
           └── Form / FAQ / Files — по сценарию
   ```

   FAQ, форму и документы размещай внутри Footer, когда они предусмотрены сценарием. Навигацию банковского приложения автоматически не добавляй.

5. **Настрой ширины областей.** Используй системные переменные колонок и разрешённые настройки Fill/Hug/Fixed из рецептов компонентов. Блоки располагаются в Body; для группировки разрешена композиция, сохраняющая системные компоненты, сетку и bindings.

6. **Настрой вертикальные интервалы.** Используй правила внешних интервалов ниже. Внутренние отступы готовых компонентов сохраняй по их рецептам; изменения контента не должны сбрасывать системные padding и bindings.

## Внешние интервалы

| Соседние блоки | Внешний интервал |
|---|---:|
| PromoMainBlock → Benefits | **24 px** |
| Benefits → следующий BenefitsBlock с пресетом Steps | **72 px** |

Расстояния измеряются между фактическими границами блоков после наполнения и пересчёта Auto Layout. Не переноси значения таблицы на другие пары блоков, mobile-web или модальное окно.

Gutter задаёт интервалы сетки и не определяет внешний вертикальный ритм. Общий `itemSpacing` допустим только для области с подтверждённым единым интервалом. Исключения реализуй разрешённой композицией, сохраняя анатомию компонентов и bindings.

Не добавляй собственные пустые Frame для имитации расстояний. Интервалы задаются настройками разрешённой Auto Layout-композиции; штатные элементы отступов библиотечных компонентов сохраняются.

Не выводи отсутствующее число из внешнего вида, raw baseline или похожего блока. Сохрани точный гэп и его влияние; зависимое решение требует доступной нормы или ответа пользователя. Остальная независимая работа может продолжаться.

## Внутренние интервалы кастомного блока

Если используется кастомный контентный блок, разрешённый [правилами выбора компонентов](component-selection.md), расстояние между его заголовком и содержимым составляет **40 px на Desktop** и **32 px в Compact**.

Для готовых библиотечных компонентов сохраняй интервалы, предусмотренные их рецептами. Эти значения не задают расстояния между соседними блоками лендинга.

## Проверить основу и наполненный результат

- До сборки каркасов проверь фактические контейнер и место размещения контента, type/key, containment, режим сетки, sizing и поверхности.
- После наполнения проверь доступную ширину, фактические интервалы между соседними секциями, высоту контейнера, переносы и допустимость выхода содержимого по рецептам. Изменения текстов и ассетов не должны сбивать соседние блоки.
- Если паттерн требует прокрутку, fixed- или sticky-области, проверь их размещение и отсутствие перекрытий.
- Проверяй согласованные размеры и состояния. Если требуется несколько Desktop-разрешений, проверь каждое; один кадр не подтверждает адаптивность, mobile или модальное размещение.

Непроверенное фиксируй как NOT_RUN, несовпадение с известной нормой — как FAIL до исправления, отсутствие самой нормы — как UNKNOWN с указанным гэпом. Проверка макета не подтверждает автоматическое соблюдение правил исполнителем.
